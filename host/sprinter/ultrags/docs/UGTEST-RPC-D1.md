# UGTEST-D1: диагностика отказа PCM/FX на R12

**Результат 22:09:** PCM/FX PASS, MIX host TIMEOUT на SNAPSHOT.
Следующий комплект — [D2](RPC-DEADLINE-D2.md), с исправленным расчётом
срока ожидания. Исходная поставка D1 сохранена без изменений.

## Аппаратный результат

После CONFIG PASS на R12 владелец сообщил PASS для `UGMEM INFO`,
`UGMEM TEST QUICK`, `UGMEM ROUNDTRIP 65537 /VERIFY`.
`UGTEST PCM` и `UGTEST FX` завершились `RESULT FAIL code=3
reason=MEMORY_OR_PROTOCOL`, с `rpc_source=0x01 status=0x03`.
Полного фото/номера RPC пока нет; наличие звука не уточнено.

Source01 — локальная ошибка host-библиотеки, status03 — LENGTH.
Возможны неверная длина wire-ответа, недостаточная ёмкость буфера или
несовпадение длины с ожидаемой конкретным вызовом; это не wire PSRAM error.
Успешная проверка памяти не доказывает надёжность всех последующих ответов.
Связь с прежними искажениями CONFIG пока не установлена.

## Изменения

Прошивка остаётся R12, SHA256
`e48ac11ef4e69958b1d57c9a706c509acd947102740b3e4ea2a53c415b3f35d5`.
Меняется только UGTEST.EXE:

- После первого SNAPSHOT добавлена пропущенная проверка carry. Ошибка
  теперь немедленно направляется в RPC_ERROR до выделения объекта.
  Сам факт этой ошибки не доказывает причину отказа на карте.
- Перед cleanup печатаются `UGTEST-D1 rpc_op`, `frame_status:len`,
  `wrapper`, `expected`, `got`. Только чтение RAM; дополнительных ISA
  запросов в этой диагностической печати нет.
- `wrapper=01`: отказ внутри UG_RPC, `got=FFFF` ещё не получен.
  `wrapper=02`: UG_RPC вернул успех, но длина не совпала с ожидаемой.
  `wrapper=00`: ошибка вне обёртки, expected/got не печатаются.
- `frame_status:len` — два сырых байта рабочего буфера. При раннем отказе
  до приёма или восстановлении внутри библиотеки они могут принадлежать
  запросу/восстановлению, поэтому сами по себе не доказывают приём заголовка.

Частые RPC (hex): 00 INFO, 01 CAPS, 10 ALLOC, 14 PCM_CONFIG,
20 WRITE_BEGIN, 21 WRITE_END, 30 PLAY_PCM, 32 CONTROL, 36 PLAY_FX,
50 SNAPSHOT. Код команды и длина печатаются в hex.

## Проверки

Две независимые сборки EXE совпадают. Остальные восемь утилит и UF2
побайтно совпадают с замороженной R12. 30 запусков фактического UGTEST.EXE
на Z80-модели с production C backend: PCM/FX/MIX; нормальная работа,
FF в длине SNAPSHOT, длина 63 вместо 64, wire-ошибка SNAPSHOT,
лишний байт ответа PCM_CONFIG. Проверены диагностика, выход, возврат
MMU/IFF/SP, предел ISA-окна и освобождение временного объекта.
Это функциональная проверка, не измерение электрического обмена.

Команда: `node tools/diagnostics/check-ugtest-rpc-d1.mjs build/r12-audio-diag`.
Отчёт: `build/r12-audio-diag/actual-exe.json`; копия и hashes в поставке.
Статус: HOST_PASS / REAL_PENDING для новой утилиты.
CONFIG R12 остаётся scoped REAL_PASS, PCM/FX — REAL_FAIL, S6/S7 IN_PROGRESS.
Замороженная R12 не изменяется; новая поставка содержит её же UF2.

## На Sprinter

**Перепрошивка не нужна.** Заменить UGTEST.EXE из нового CURRENT.ZIP/IMG
или скопировать отдельный `build/latest/UGTEST.EXE` в каталог запуска.
Остановить ранее запущенное воспроизведение, если оно есть.

```text
UGTEST PCM
```

При FAIL прислать полный вывод, особенно новую строку `UGTEST-D1`.
До разбора ошибки FX/MIX повторять не требуется.
Если PCM прошёл, выполнить `UGTEST FX` и прислать результат.
SAVE, смена режима и загрузка другой UF2 не требуются.
