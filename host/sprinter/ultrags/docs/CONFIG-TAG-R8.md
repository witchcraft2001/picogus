# R8: исправление метки ISA-цикла и счётчика защиты

Статус после фото 16:24:44: **HOST PASS / REAL FAIL**. Native STATUS01/ERROR00
восстановлены, но переход в ULTRAGS по-прежнему TIMEOUT. Разбор и проверка
без перепрошивки: [CONFIG-R8-FOLLOWUP.md](CONFIG-R8-FOLLOWUP.md).
Ниже сохранено описание кандидата исправления R7,
аппаратный запуск на E1MAGIC ещё не подтверждён. S6/S7 IN_PROGRESS.

## Что было сломано

В последней работавшей версии (`c711958`) PIO явно помечал собственное
чтение инверсией захваченного слова. При переработке ISA для точных GS-портов
и общей программы IOW/IOR эта метка была заменена на чтение GPIO26 из
снимка входов. GPIO26 — общий выход WAIT двух автоматов, с задержкой
обратного чтения. Он не является меткой принадлежности конкретного цикла.

Воспроизводимые дефекты:

1. Если собственный цикл уже выставил WAIT, но входной снимок GPIO26 ещё
   содержит 0, native-чтение отбрасывается как чужое. Ответ не выставляется,
   программный флаг `waiting` остаётся false, поэтому IO_END не снимает
   выставленный PIO WAIT. Обратная ошибка при GPIO26=1 — чужой цикл получает
   признак собственного. Декодер портов ограничивает последствия, но контракт
   между PIO и ARM уже нарушен.
2. `ug_handshake_put()` увеличивал `completions` для любого финального
   вердикта, включая отброшенный чужой цикл. Такие операции могли постоянно
   откладывать защиту при оставшемся WAIT. Поэтому код 4 не исключал этот
   сценарий, а код 5 мог появиться после прекращения потока операций.

Результат R7 на плате: TIMEOUT, TRC0 целиком FF, позднее замечен LED5.
Сам переход LED4→5 не наблюдался; 1–2 минуты — время обнаружения.
Локально воспроизведена цепочка «ошибочная метка → нет ответа → WAIT
не снят → защита». **Электрическая причина конкретного снимка GPIO26 на
E1MAGIC не измерена**; нельзя объявлять все аппаратные отказы объяснёнными.

## Исправление

- ISR захватывает адрес и активный `/IOR` или `/IOW` до классификации.
  Собственная ветвь PIO инвертирует этот снимок; ARM распознаёт инверсию
  по биту активного строба и восстанавливает адрес. GPIO26 в решении
  о принадлежности больше не участвует.
- Для IOW метка берётся из первого, адресного слова; второе слово содержит
  обычные данные. Для IOR остаётся одно слово и автономный выходной хвост.
- Программа по-прежнему занимает 32 слова. Для размещения явной метки
  цикл установки ADS использует уже декодированный X: CONFIG X=14 даёт
  16 тактов; native/alias X≥16 — минимум 18; GS X=19/27 — 21/29.
  Минимум обслуживаемых записей не короче прежнего GUS-интервала.
- Чужие/устаревшие захваты без ответа и без снятия собственного WAIT больше
  не считаются завершёнными операциями для guard.
- Сохранены точные GS-порты 00B3/00BB, DACK-фильтр, защита и LED1–9.
  Формат API, Settings и host-команды не менялись.

Предположение явной метки: ISA-строб активен при начальном захвате адреса
после WAIT low. Тестируются нормальные ISA-циклы; электрические пределы
очень коротких импульсов и аналоговые задержки остаются предметом REAL.
Модели не заменяют измерение шины и проверку соседней ISA-карты.

## Проверки

- Матрица generated PIO: 512 карт портов, 1 048 576 адресных случаев,
  288 INFO+CRC потоков; точный GS decode, DACK, задержки ARM, заполненный RX.
- 24 576 случаев с независимым GPIO26=0/1: R7 даёт 524 ложных отрицательных
  и 11 764 ложных положительных метки, R8 — 0 расхождений.
  Это намеренная инъекция входного уровня, не статистика отказов платы.
- Независимый rp2040js 1.4.1: 8192 захвата, выдача native/GS-ответа
  и освобождение линий после IOR.
- Production C guard с LED ON/OFF: чужие вердикты не маскируют зависший
  WAIT. Возврат прежнего безусловного увеличения `completions` проваливает
  эту проверку.
- CONFIG production C: 213 операций; finite write window: 3072 случая;
  связанный ARM capture/verdict: задержанные и устаревшие CONFIG-чтения.
- Production LED, SRAM/Settings и статический стек.
- Две независимые MULTIFW сборки и проверка идентичности шести других
  режимов. Отчёты и SHA256 включены в `R8.json` и `r8-evidence/`.

## Что запускать на Sprinter

Комплект всегда в **`build/latest/`**: прошивка `CURRENT.UF2`,
архив `CURRENT.ZIP`, инструкция `NOTES.MD`. UG EXE и TRC0/1 не менялись.

Прошивать извлечённую из ISA карту при выключенном Sprinter. После записи
отключить USB, установить карту при выключенном питании, затем включить
Sprinter. Одновременное подключение работающего Sprinter к Mac не требуется.

Слот 0:

```text
UGCFG GUS
UGCFG ULTRAGS
```

Если первая команда не прошла — остановиться и сохранить её вывод.

Если ULTRAGS прошёл:

```text
UGCFG INFO /DIAG
UGMEM INFO
```

Ожидаются активный ULTRAGS, READY, RESULT PASS и полный свободный пул.
Затем оставить командную строку на две минуты и повторить:

```text
UGCFG INFO
```

Если ULTRAGS дал TIMEOUT:

```text
TRC0
```

До TRC0 не выполнять INFO/SAVE/REBOOT/переключение режима. Сохранить полный
вывод и число вспышек сразу после команды и через две минуты.
Повторять TRC0 после LED5 не требуется: защита уже отключила ISA.
Для известного слота 1: `/SLOT:1` у каждой UG-команды и `TRC1` вместо TRC0.

SAVE, тесты аудио/GS и массовой передачи следует продолжить после успешной
проверки запуска. R8 с диагностическим IRQ не является приёмкой аудио
или производительности.
