# UltraGS: руководство программиста

UltraGS - звуковая карта для Sprinter, один из режимов работы платы PicoGUS.
Это руководство объясняет, как программа на Z80 загружает в карту звуки,
запускает музыку и эффекты и следит за состоянием карты. Оно рассчитано на
программиста, который читает ассемблер Z80 (`LD`, `CALL`, `RET`, переходы)
и пишет для DSS. Знакомство с General Sound полезно, но не требуется.

Как читать. Глава 1 вводит понятия, без которых остальное непонятно: объект,
запуск, голос, два интерфейса карты. Глава 2 - подробно разобранная первая
программа: она собирается и работает. Главы 3-8 описывают расширенный API
UltraGS: обмен, память, воспроизведение, потоковую подачу и наблюдение за
картой. Глава 9 посвящена командам General Sound, глава 10 - синтезатору
OPL2. Приложения содержат справочные таблицы: порты, коды ошибок, точные
форматы всех команд. К ним обращаются во время написания своей программы.

Все листинги взяты из собираемых примеров в каталоге `examples/`; как их
собрать и запустить, описано в [README](../README.md). Текущая версия
интерфейса - API 1.0 / VLS1. Редакция 8, 28 октября 2026 года.

## 1. Карта глазами программиста

### 1.1. Что умеет карта

Карта сама формирует звук из данных, которые ей передала программа. После
команды воспроизведения Z80 свободен: он может рисовать экран, читать
клавиатуру или грузить следующий файл, а музыка продолжает играть.

| Вид звука | Что передаёт программа | Для чего удобно |
|---|---|---|
| RAW PCM | Массив отсчётов; частоту и формат сообщает отдельной командой | Короткие эффекты, собственный генератор звука |
| WAV PCM | Файл с заголовком; частоту и формат карта берёт из него | Записанная речь, звуки, музыка |
| WAV IMA ADPCM | Файл WAV со сжатием IMA ADPCM (кодек 0x11); карта распаковывает его при воспроизведении | То же при вчетверо меньшем объёме данных |
| MOD, S3M | Модуль трекера: инструменты и ноты | Фоновая музыка; ноты разбирает карта, а не Z80 |
| OPL2 | Настройки регистров синтезатора и нажатия клавиш | Синтез без загрузки отсчётов, совместимость с AdLib |

**Отсчёт** - одно число, описывающее мгновенное значение звуковой волны;
**PCM** - запись звука последовательностью отсчётов. Карта принимает отсчёты
8 или 16 бит, mono или stereo, с частотой от 8000 до 48000 в секунду, а на
выход всегда выдаёт 48000 Гц stereo 16 бит. Файлы WAV со сжатием IMA ADPCM
(4 бита на отсчёт) карта распаковывает сама.

Для хранения звуков на плате есть 8 МиБ памяти. Она не видна в адресном
пространстве Z80: записать или прочитать её можно только командами карты.
Загруженные данные остаются в ней, пока программа их не удалит или карту не
сбросят.

Одновременно карта смешивает до 32 **голосов**. Голос - один канал
воспроизведения PCM: mono-эффект занимает один голос, stereo-эффект - два,
четырёхканальный MOD - четыре, восьмиканальный - восемь. Синтезатор OPL2
работает отдельно и голоса не расходует.

### 1.2. Объекты, запуски и голоса

У каждого звука на карте три разных номера, и их важно не путать.

**Объект** - это данные, хранящиеся в памяти карты: массив отсчётов, файл WAV
или MOD. Карта выдаёт объекту номер - **handle**. Handle не является адресом
памяти и не выбирается программистом: его возвращает команда ALLOC, и его
нужно сохранить.

**Запуск** (instance) - отдельное воспроизведение объекта. Один и тот же
объект можно запустить несколько раз; каждый запуск получает свой номер -
**play_id** для основного звука или **instance_id** для эффекта. Останавливают
запуск, а удаляют объект.

**Голос** - физический ресурс микшера, который карта назначает запуску сама.
Программа обычно о голосах не думает; номера голосов нужны только при чтении
состояния карты.

Пример. Программа загрузила stereo WAV и получила handle 17. Она запустила
его дважды как эффект и получила номера запусков 5 и 6. Данные хранятся один
раз, но голосов занято четыре: по два на каждый stereo-запуск. STOP_FX(5)
остановит только первый запуск. FREE(17) сразу после этого вернёт ошибку
PINNED: объект ещё используется вторым запуском. После STOP_FX(6) объект
можно удалить. Числа здесь условные: реальные значения всегда берут из ответов
карты.

Основной звук один: MOD, S3M, PCM или поток. Он называется **foreground**.
Независимые эффекты (FX) играют поверх него, и остановка музыки их не
затрагивает. Новый PLAY основного звука заменяет предыдущий.

### 1.3. Два интерфейса

Для новой программы используйте **расширенный API UltraGS**. Это набор
команд с номерами и аргументами фиксированного формата: выделить память,
загрузить, запустить, приостановить, прочитать состояние. Именно его
показывает глава 2, и для него есть готовая библиотека Z80.

**Команды General Sound** могут использоваться для лёгкого портирования программ, уже написанных для GS: они
загружают модуль побайтно, управляют им однобайтовыми командами и читают флаги.
UltraGS исполняет музыкальные команды GS 1.04 с дополнениями 1.05 (глава 9),
но не эмулирует саму плату: внутреннего Z80 и его RAM нет, команды POKE/PEEK/
CALL не выполняются, MP3-декодер и SD-карта NeoGS не предоставляются.

Оба интерфейса работают с одной памятью и одним основным звуком. Музыка,
запущенная командами GS, видна расширенному API и наоборот.

### 1.4. Библиотека для Z80

Библиотека `ugproto.asm` берёт на себя обмен с портами карты. Программа
вызывает несколько процедур:

| Процедура | Регистры на входе | Назначение |
|---|---|---|
| `UG_LIB_INIT` | - | Обнулить переменные библиотеки; вызывается первой |
| `UG_OPEN` | A = слот (0 или 1), HL = BASE | Найти карту, проверить режим UltraGS, запомнить адрес |
| `UG_RPC` | A = код команды, HL = аргументы, BC = их длина, DE = буфер ответа, IX = его размер | Выполнить команду расширенного API |
| `UG_WRITE` / `UG_READ` | HL = handle, DE = буфер Z80, BC = длина 1..1024, A = способ передачи, `UG_OFFSET` = смещение | Передать блок данных на карту или с карты |
| `UG_GS_COMMAND` | HL = 9-байтовое описание команды | Выполнить команду General Sound |
| `UG_GS_SD` / `UG_GS_WD` | A = байт (для `UG_GS_SD`) | Отдельные шаги обмена GS: записать байт в DATA и дождаться, пока карта его заберёт (9.1) |
| `UG_ISA_OPEN` / `UG_ISA_CLOSE` | A = слот, HL = адрес порта ISA (для `UG_ISA_OPEN`) | Открыть окно ISA для прямого обращения к портам, например OPL2 (10.1), и закрыть его |
| `UG_SNAPSHOT` | HL = буфер 128 байт | Получить снимок состояния (то же, что команда SNAPSHOT) |
| `UG_XCTRL` | A = управляющее значение | Служебные действия: сброс обмена, отмена передачи |
| `UG_FRAME_CRC` | A = 0 или 1 | Включить контрольную сумму команд и ответов |
| `UG_CLOSE` | - | Завершить работу с картой |

Соглашения одинаковы для всех процедур. После вызова установленный флаг
переноса (CF=1) означает ошибку, её код находится в A; при успехе CF=0.
`UG_RPC` дополнительно возвращает в BC фактическую длину ответа - её
обязательно сравнивают с ожидаемой. Регистры IX и IY сохраняются; AF, BC, DE,
HL и альтернативный набор могут измениться. Библиотека не рассчитана на
вызов из обработчика прерываний.

Обращаясь к карте, библиотека на короткое время отображает порты ISA в
область памяти C000h..FFFFh и закрывает это окно перед возвратом. Поэтому код,
стек и буферы программы должны лежать ниже C000h. Закрывая окно, библиотека
возвращает прежние PAGE3 и флаг прерываний, а в порт SYSTEM (1FFDh) пишет
стандартное для DSS значение 01h: прочитать прежнее нельзя, порт только для
записи. Окна 0-2 библиотека не трогает. Между вызовами окно закрыто, и
программа может свободно вызывать DSS. Длинные передачи библиотека сама
разбивает на короткие порции, так что прерывания не блокируются надолго.

Числовые коды команд, размеры аргументов и ответов, флаги и коды ошибок
определены в генерируемом файле `ug_wire.inc`. В примерах встречаются имена
`UG_OP_…` (код команды), `UG_OP_…_REQ_LEN` и `UG_OP_…_RESP_LEN` (размеры
аргументов и ответа), `UG_ERR_…` (коды ошибок), `UG_KIND_…` (виды объектов),
`UG_TRANSPORT_…` (способы передачи), `UG_MOD_…` (флаги PLAY_MOD),
`UG_VOICE_AUTO` (выбор голоса картой), `UG_XC_…` (действия `UG_XCTRL`) и
`UG_GS_GS_…` (коды команд General Sound). В коде лучше писать имя, а не
число.

#### Варианты сборки

Перед `INCLUDE "ugproto.asm"` программа задаёт определения, от которых
зависит, как библиотека ждёт ответа карты и как обращается с частотой
процессора. Примеры руководства собраны с `UG_NO_DSS`; сами программы при
этом вызывают DSS для чтения часов и клавиатуры.

| Определение | Что делает библиотека |
|---|---|
| `UG_NO_DSS` | Не вызывает DSS. Срок ожидания отсчитывает числом опросов карты, ESC сама не проверяет |
| `UG_DSS_TIMED` | Отмеряет сроки по часам DSS; ESC прерывает долгое ожидание с кодом CANCELLED (15h) |
| `UG_ISA_TURBO_OFF` | Выключает Turbo на время каждого обращения к карте, после него включает |

Из `UG_NO_DSS` и `UG_DSS_TIMED` выбирают одно. `UG_ISA_TURBO_OFF` сочетается
с любым из них и нужен редко, см. ниже.

**Без DSS.** Такая сборка полезна, если программа должна исключить обращения
к DSS, например потому что сама распоряжается памятью и прерываниями.
Сроки рассчитаны на 21 МГц и на медленном процессоре только удлиняются:
обычная команда ждёт ответа не меньше секунды, SEAL - не меньше 30 с.
Чтобы долгое ожидание можно было прервать, программа определяет процедуру
`UG_POLL_HOOK`. Библиотека вызывает её между опросами карты при закрытом
окне ISA; CF=1 на выходе прерывает ожидание, и вызов библиотеки возвращает
CANCELLED. Процедура может менять любые регистры, кроме SP:

```asm
    DEFINE UG_NO_DSS
    DEFINE UG_POLL_HOOK game_poll   ; необязательно
...
game_poll:                         ; CF=1 - прервать ожидание карты
    ld a,(quit_request)            ; 1, если обработчик клавиатуры игры
    rra                            ; заметил выход: бит 0 уходит в CF
    ret
```

**Частота процессора.** Библиотека не меняет частоту: обмен с картой идёт
в том режиме, который выбрала программа, обычно в Turbo. Порты карты на это
рассчитаны, кроме двух случаев:

| Порты | Ограничение |
|---|---|
| 1D0h-1D2h, настройка карты | Доступны только при выключенном Turbo. Библиотека их не использует: `UG_OPEN` узнаёт карту по её регистрам и команде INFO. Настройки меняет `UGCFG` |
| 388h, состояние OPL2 | Чтение надёжно в Turbo, пока в настройках карты не включён дополнительный блок портов BULK alias вне 380h-39Fh (по умолчанию он выключен). Запись регистров ограничения не имеет |

Из-за первого случая `UG_OPEN` должен заранее знать адрес BASE: по умолчанию
02A0h, его задаёт `UGCFG`. Карта в другом режиме для него выглядит как
отсутствующая: он возвращает TIMEOUT.

Если на конкретном компьютере обмен по ISA при включённом Turbo нестабилен,
соберите программу с `UG_ISA_TURBO_OFF`. Тогда библиотека проводит каждое
обращение к карте на пониженной частоте, а по его окончании включает Turbo,
как принято в DSS. Между вызовами программа работает на обычной скорости, но
сами передачи данных становятся медленнее. В этой сборке `UG_OPEN` узнаёт
карту через порты настройки, поэтому неверный режим карты даёт STATE.

## 2. Первый звук: низкий тон из собственного массива

**Задача:** получить короткий гудок без WAV-файла и без музыкального модуля.
Программа создаст массив из 256 байт, загрузит его в карту, будет повторять
примерно 1-2 секунды, затем остановит звук и освободит память. ESC позволяет
закончить раньше. При успешном выходе загруженный массив на карте не остаётся.

Все фрагменты ниже взяты из [firstpcm.asm](../examples/firstpcm.asm).
Они являются частями одной программы, а не отдельными EXE. Библиотечные
процедуры начинаются с `UG_`; остальные, например `upload_sound`, написаны
в самом примере и разобраны ниже. Полный файл содержит также заголовок EXE,
общий выход и обработку ошибок.

Карта должна быть переведена в режим UltraGS утилитой `UGCFG`. Перед работой
программа приводит карту в исходное состояние: останавливает звук и удаляет
объекты, оставшиеся от предыдущих программ (3.5). Других программ,
управляющих картой одновременно с этой, быть не должно.

### 2.1. Обратиться к нужной карте

Сначала библиотеке нужно сообщить, **где находится карта**. Здесь два
независимых параметра:

| Параметр | Значение в примере | Что оно означает |
|---|---|---|
| Номер слота | `DOC_SLOT`, по умолчанию 0 | В какой ISA-слот Sprinter установлена карта: 0 или 1 |
| Базовый адрес портов | `CARD_IO_BASE`, равный `02A0h` | С какого номера начинаются порты UltraGS на шине ISA |

`DOC_SLOT` задаётся при сборке ключом ассемблера `-DDOC_SLOT=0` или
`-DDOC_SLOT=1`; без ключа используется 0. Так из одного исходника получаются
`PCM0.EXE` для первого слота и `PCM1.EXE` для второго.

**Порт** - адрес, по которому компьютер обращается к регистру устройства:
передаёт команду или читает ответ. Карта занимает 32 соседних порта; адрес
первого из них называют **базовым**, или BASE. `02A0h` - стандартная
настройка UltraGS. Текущий адрес показывает `UGCFG INFO`, а `UGCFG PORTS`
позволяет его изменить. `UG_OPEN` только использует уже установленный адрес,
но не меняет настройки карты.

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#card-address -->

```asm
CARD_IO_BASE EQU 0x02A0       ; первый порт UltraGS на шине ISA
```

<!-- /snippet -->

Далее передаём библиотеке номер слота через регистр A, а адрес портов через
пару HL:

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#open-card -->

```asm
    call UG_LIB_INIT         ; подготовить переменные библиотеки
    ld a,DOC_SLOT            ; слот с картой: 0 или 1
    ld hl,CARD_IO_BASE       ; адрес первого порта карты
    call UG_OPEN             ; проверить, что карта отвечает
    ret c                    ; при ошибке вернуться к общему выходу
```

<!-- /snippet -->

`UG_LIB_INIT` подготавливает переменные библиотеки в памяти Z80.
`UG_OPEN` проверяет ответ карты и запоминает, куда обращаться при следующих
вызовах. **Звука после этого ещё нет:** массив пока не загружен и команда
воспроизведения не дана.

`RET C` после каждого вызова означает: при ошибке вернуться к общему выходу
программы, не продолжая работу с картой. Код ошибки остаётся в A.

В полном примере после открытия также проверяются версия карты, наличие
нужных функций, затем сброс карты в исходное состояние. Эти служебные шаги
выполняет `check_card`; её текст разобран в 3.1 и 3.5.

### 2.2. Подготовить числа, которые станут звуком

Выберем простой формат **U8 mono**. U8 означает, что один отсчёт занимает
один беззнаковый байт со значением 0..255. Середина этого диапазона - 128.
Массив из одних значений 128 даёт тишину. Если значения периодически меняются
выше и ниже середины, получается тон.

Наш массив содержит 32 значения 144, затем 32 значения 112. Это один период
волны из 64 отсчётов. Повторим его четыре раза и получим 256 байт.
`DUP`/`EDUP` в sjasmplus повторяют указанную группу при сборке; `DB` записывает
байт в программу. Здесь ещё ничего не передаётся карте.

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#samples -->

```asm
samples:
    DUP 4                    ; четыре одинаковых периода волны
        DUP 32
            DB 144           ; 32 отсчёта выше середины
        EDUP
        DUP 32
            DB 112           ; 32 отсчёта ниже середины
        EDUP
    EDUP
    ASSERT $-samples == TONE_BYTES ; 4 * (32 + 32) = 256 байт
```

<!-- /snippet -->

Читать эти числа карта будет с частотой 8000 отсчётов в секунду. Один период
занимает 64 отсчёта, поэтому основная частота гудка будет **8000 / 64 = 125 Гц**.
Весь массив длится только 256 / 8000 = 0,032 секунды; чтобы услышать длинный
гудок, позднее включим повтор массива до команды остановки.

Настройки примера вынесены в начало исходника. Их названия используются
дальше вместо чисел, смысл которых пришлось бы вспоминать:

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#tone-settings -->

```asm
TONE_RATE   EQU 8000         ; 8000 отсчётов звука в секунду
TONE_BYTES  EQU 256          ; длина нашего массива в байтах
TONE_GAIN   EQU 16           ; громкость: 0 = тишина, 64 = максимум
PAN_CENTER  EQU 128          ; по центру между левым и правым выходами
PCM_U8      EQU 0            ; формат: один беззнаковый байт на отсчёт
```

<!-- /snippet -->

### 2.3. Выделить память

Команда **ALLOC** создаёт место для нового звука в памяти карты. Ей нужно
передать вид данных и размер. Для этого подготовим небольшой блок аргументов
в памяти Z80:

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#alloc-params -->

```asm
alloc_request:
    DB UG_KIND_RAW_PCM       ; будут обычные отсчёты, без заголовка файла
    DD TONE_BYTES            ; нужно 256 байт памяти на карте
```

<!-- /snippet -->

`UG_KIND_RAW_PCM` означает массив отсчётов без файлового заголовка. `DD`
записывает четырёхбайтовое число. Поэтому аргументы занимают **1 + 4 = 5 байт**.
Сами 256 звуковых байт в эти пять байт не входят: их передадим следующим шагом.

Отправка команды выглядит так:

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#allocate-sound -->

```asm
    ld a,UG_OP_ALLOC         ; команда: выделить память
    ld hl,alloc_request      ; адрес её аргументов в памяти Z80
    ld bc,UG_OP_ALLOC_REQ_LEN ; размер аргументов: 5 байт
    ld ix,UG_OP_ALLOC_RESP_LEN ; ожидаем ответ из 6 байт
    call rpc                 ; отправить команду, получить response
    ret c                    ; ошибка: следующий шаг не выполнять
    ld hl,(response)         ; первые 2 байта: номер нового объекта
    ld (sound_handle),hl     ; запомнить этот номер
```

<!-- /snippet -->

Здесь `rpc` - небольшая процедура нашего примера: она подставляет адрес
буфера ответа, вызывает `UG_RPC` и проверяет, что длина ответа совпала с
ожидаемой. У всех её вызовов один и тот же смысл параметров:

| Регистр | Что передаём |
|---|---|
| A | Какую команду выполнить, например `UG_OP_ALLOC` |
| HL | Где в памяти Z80 лежат её аргументы |
| BC | Сколько байт занимают аргументы |
| IX | Сколько байт данных должно прийти в ответ |

Вот она целиком. `response` - буфер на 128 байт в памяти Z80, куда `UG_RPC`
кладёт данные ответа:

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#rpc -->

```asm
; A = команда, HL = аргументы, BC = их длина, IX = ожидаемая длина ответа.
; Ответ попадает в response; другая длина ответа считается ошибкой LENGTH.
rpc:
    ld de,response           ; буфер ответа, 128 байт
    call UG_RPC
    ret c
    push ix
    pop hl
    or a
    sbc hl,bc                ; длина ответа должна совпасть с ожидаемой
    ret z
    ld a,UG_ERR_LENGTH
    scf
    ret
```

<!-- /snippet -->

За именем `UG_OP_ALLOC` стоит код команды 10h. Для ALLOC ответ состоит из
двухбайтового номера объекта и четырёхбайтового фактического размера
выделенной памяти: всего шесть байт.

`rpc` помещает ответ в массив `response`. Команда `LD HL,(response)` читает
из его начала двухбайтовый **номер выделенного объекта**. Сохраняем номер
в переменной `sound_handle`. Например, карта может вернуть 5; тогда дальнейшие
операции с этим звуком используют 5. В другой раз номер может быть другим.
Вручную подставлять постоянный номер нельзя.

### 2.4. Скопировать массив на карту

Место выделено, но звуковых данных в нём пока нет. Передадим массив `samples`
из памяти Z80 в объект с полученным номером:

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#upload-sound -->

```asm
upload_sound:
    ld hl,0
    ld (UG_OFFSET),hl        ; смещение = 0: пишем с начала объекта
    ld (UG_OFFSET+2),hl      ; смещение занимает 4 байта, обнуляем оба слова
    ld hl,(sound_handle)     ; куда: объект в памяти карты
    ld de,samples            ; откуда: массив в памяти Z80
    ld bc,TONE_BYTES         ; сколько: 256 байт
    ld a,UG_TRANSPORT_BULK_VERIFIED ; передача с проверкой целостности
    call UG_WRITE
    ret
```

<!-- /snippet -->

У `UG_WRITE` параметры отличаются от `rpc`: **HL выбирает объект на карте,
DE указывает исходный массив Z80, BC задаёт количество байтов**.
`UG_OFFSET` задаёт смещение внутри объекта. Сейчас оно равно нулю, поэтому
запись начинается с первого байта. Смещение четырёхбайтовое; Z80 записывает
его двумя двухбайтовыми командами.

`UG_TRANSPORT_BULK_VERIFIED` выбирает передачу с проверкой контрольной суммы.
Библиотека сама договаривается с картой о передаче, отправляет блок и проверяет
результат. При ошибке она вернёт CF=1, и наш пример перейдёт к завершению.
Писать свой цикл обращения к ISA-портам для этой задачи не требуется.

После успешного `UG_WRITE` копия массива находится на карте. Звук ещё не
начался: карта пока не знает, с какой частотой и в каком формате его читать.

### 2.5. Сообщить карте, как читать массив

Одинаковые байты можно понимать как mono или stereo, как 8-битные или
16-битные значения, читать медленно или быстро. Команда **PCM_CONFIG**
сообщает, как именно следует воспроизводить наш RAW-объект.
В этом описании `DW` занимает два байта, `DD` - четыре, `DB` - один.

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#pcm-params -->

```asm
pcm_request:
    DW 0                     ; сюда allocate_sound запишет sound_handle
    DD TONE_RATE             ; частота: 8000 отсчётов в секунду
    DB 1                     ; один канал: mono
    DB 8                     ; 8 бит, то есть один байт на отсчёт
    DB PCM_U8                ; значения от 0 до 255, середина = 128
    DB 0                     ; внутренняя петля не используется
    DD 0                     ; отсчёты начинаются с первого байта объекта
    DD TONE_BYTES            ; длина массива в байтах
    DD 0                     ; начало внутренней петли: не используется
    DD 0                     ; конец внутренней петли: не используется
```

<!-- /snippet -->

Первое `DW 0` - место под номер объекта. Процедура `allocate_sound` уже
записала туда полученный `sound_handle`. Остальные поля описывают выбранный
звук: один канал, один байт на отсчёт, частота 8000 Гц, длина 256 байт.
Внутренняя петля позволила бы повторять часть массива; здесь она выключена.

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#describe-sound -->

```asm
describe_sound:
    ld a,UG_OP_PCM_CONFIG    ; команда: описать содержимое RAW
    ld hl,pcm_request        ; номер объекта, частота, формат, длина
    ld bc,UG_OP_PCM_CONFIG_REQ_LEN ; 26 байт аргументов
    ld ix,0                  ; данных в ответе нет, только успех/ошибка
    call rpc
    ret
```

<!-- /snippet -->

**SEAL** означает «загрузка закончена, проверь объект». После этой команды
карта разрешает использовать объект для воспроизведения. До SEAL он ещё
считается загружаемым, даже если все байты уже переданы.

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#seal-params -->

```asm
seal_request:
    DW 0                     ; сюда allocate_sound запишет sound_handle
    DB 0                     ; не задаём ожидаемую CRC всего объекта
    DD 0                     ; это поле тогда должно быть нулём
```

<!-- /snippet -->

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#seal-sound -->

```asm
seal_sound:
    ld a,UG_OP_SEAL          ; команда: проверить и завершить загрузку
    ld hl,seal_request
    ld bc,UG_OP_SEAL_REQ_LEN ; 7 байт аргументов
    ld ix,UG_OP_SEAL_RESP_LEN ; 4 байта контрольной суммы в ответе
    call rpc
    ret
```

<!-- /snippet -->

CRC - контрольная сумма для проверки целостности данных. В этом примере
UG_WRITE уже проверил переданный блок. Поэтому дополнительное сравнение
с заранее вычисленной CRC всего объекта выключено: оба поля после номера
объекта нулевые. SEAL всё равно проверяет формат и возвращает вычисленную CRC.
Порядок вызовов одинаков для своих звуков: загрузить данные, описать RAW,
завершить загрузку, затем воспроизводить.

### 2.6. Включить звук

Теперь объект готов. Команде **PLAY_PCM** задаём его номер, количество
повторов, громкость и положение между левым и правым выходами:

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#play-params -->

```asm
play_request:
    DW 0                     ; сюда allocate_sound запишет sound_handle
    DW 0                     ; повторять весь объект до команды STOP
    DB TONE_GAIN             ; небольшая громкость, 16 из 64
    DB PAN_CENTER            ; одинаковая громкость слева и справа
```

<!-- /snippet -->

Первое слово уже заполнено номером объекта. Второе слово равно нулю:
для этой команды **ноль означает повторять весь объект до STOP**.
Значение 1 означало бы один проход, то есть для нашего массива всего
0,032 секунды. Pan=128 воспроизводит mono с одинаковой громкостью слева
и справа; 0 перемещает звук влево, 255 - вправо.

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#start-sound -->

```asm
start_sound:
    ld a,UG_OP_PLAY_PCM      ; команда: воспроизвести объект
    ld hl,play_request       ; номер объекта, повторы, громкость, панорама
    ld bc,UG_OP_PLAY_PCM_REQ_LEN ; 6 байт аргументов
    ld ix,UG_OP_PLAY_PCM_RESP_LEN ; 2 байта: номер запуска
    call rpc
    ret c
    ld hl,(response)
    ld (play_id),hl           ; нужен для остановки именно этого запуска
    xor a
    ret
```

<!-- /snippet -->

После успешного вызова слышен низкий непрерывный тон. Карта повторяет массив
сама: Z80 не должен снова и снова передавать те же 256 байт.

В ответ приходит **play_id - номер запуска**. Это другой номер, чем
`sound_handle`. Номер объекта выбирает хранящиеся данные; номер запуска
выбирает их текущее воспроизведение. Например, объект 5 может быть запущен
с номером запуска 12. Останавливать нужно запуск 12, а удалять из памяти -
объект 5. Оба номера в примере сохраняются из ответов карты.

### 2.7. Остановить звук и вернуть память

Остановка и удаление данных - два отдельных действия. Чтобы остановить
наш тон, отправляем CONTROL с номером запуска и действием STOP:

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#stop-params -->

```asm
stop_request:
    DW 0                     ; сюда stop_sound запишет play_id
    DB 0                     ; действие 0 = STOP (остановить)
```

<!-- /snippet -->

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#stop-sound -->

```asm
stop_sound:
    ld hl,(play_id)           ; номер запуска, который требуется остановить
    ld (stop_request),hl
    ld a,UG_OP_CONTROL       ; управление воспроизведением
    ld hl,stop_request       ; номер запуска и действие STOP
    ld bc,UG_OP_CONTROL_REQ_LEN ; 3 байта аргументов
    ld ix,0                  ; ответ без дополнительных данных
    call rpc
    ret
```

<!-- /snippet -->

После остановки объект остаётся на карте, и его можно было бы запустить
снова. В нашем примере он больше не нужен, поэтому удаляем его командой FREE:

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#free-sound -->

```asm
free_sound:
    ld a,UG_OP_FREE          ; команда: удалить объект из памяти карты
    ld hl,sound_handle       ; адрес переменной с номером объекта
    ld bc,UG_OP_FREE_REQ_LEN ; номер занимает 2 байта
    ld ix,0                  ; ответ без дополнительных данных
    call rpc
    ret
```

<!-- /snippet -->

Здесь `LD HL,sound_handle` передаёт **адрес переменной** с номером объекта,
потому что `rpc` читает аргументы по адресу HL. При загрузке в `UG_WRITE`
использовалось `LD HL,(sound_handle)`: та процедура принимала сам номер.
Скобки в этих двух вызовах имеют значение.

Воспроизведение останавливает звуковая часть карты. Она может ещё не успеть
применить STOP к моменту первого FREE. Тогда придёт PINNED - «данные ещё
используются». В полном примере процедура `cleanup` ограниченно ждёт
и повторяет FREE. Она вызывается и при обычном выходе, и при ESC, и при ошибке.
После очистки UG_CLOSE завершает работу с библиотекой. Сам UG_CLOSE не
заменяет остановку звука и освобождение его памяти.

### 2.8. Дополнительная проверка: прочитать свои байты обратно

Чтобы убедиться, что в памяти карты лежит именно наш массив, пример также
вызывает `verify_sound` перед воспроизведением. Эта проверка полезна при
отладке загрузчика. Для самого звучания чтение обратно не требуется.

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#verify-sound -->

```asm
verify_sound:
    ld hl,(sound_handle)     ; читаем тот же объект
    ld de,readback           ; но в другой массив памяти Z80
    ld bc,TONE_BYTES
    ld a,UG_TRANSPORT_BULK_VERIFIED
    call UG_READ             ; UG_OFFSET остался равен нулю
    ret c
    ld hl,readback
    ld de,samples
    ld b,0                   ; цикл DJNZ при B=0 выполнит 256 сравнений
    call compare             ; проверить все прочитанные байты
    ret
```

<!-- /snippet -->

`readback` - отдельный буфер на 256 байт в памяти Z80. Подпрограмма `compare`
сравнивает B байт по адресам HL и DE и при первом отличии возвращает CF=1 с
кодом STATE:

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#compare -->

```asm
; HL и DE = два массива, B = число байт. При первом отличии CF=1, A = STATE.
compare:
    ld a,(de)
    cp (hl)
    jr nz,.bad
    inc hl
    inc de
    djnz compare
    xor a
    ret
.bad:
    ld a,UG_ERR_STATE        ; байты не совпали
    scf
    ret
```

<!-- /snippet -->

Ноль в B использован из-за поведения команды DJNZ: после первого уменьшения
он становится 255, поэтому весь цикл выполняется 256 раз.

### 2.9. Вся последовательность и первые изменения

Все разобранные шаги вызываются одной процедурой. `RET C` после каждого
шага означает: если он не удался, дальнейшие действия со звуком не выполнять.
Выход из `play_tone` всегда ведёт к общей очистке программы.

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#tone-sequence -->

```asm
play_tone:
    call allocate_sound      ; получить место в памяти карты
    ret c
    call upload_sound        ; скопировать туда массив samples
    ret c
    call describe_sound      ; задать частоту и формат массива
    ret c
    call seal_sound          ; подтвердить: загрузка закончена
    ret c
    call verify_sound        ; прочитать обратно и сравнить
    ret c
    call start_sound         ; теперь включить воспроизведение
    ret c
    call wait_tone           ; подождать 1-2 секунды или ESC
    ret
```

<!-- /snippet -->

`wait_tone` ждёт по часам DSS, проверяет ESC и наличие ошибки звука. Через
1-2 секунды или при ESC управление возвращается к общему выходу. Ожидания
ограничены, поэтому неисправность карты или часов не должна повесить программу.

Попробуйте изменить один параметр и сравнить результат:

| Изменение | Что должно произойти |
|---|---|
| `TONE_RATE = 16000` вместо 8000 | Тот же массив читается вдвое быстрее: тон станет 250 Гц |
| `TONE_GAIN = 8` вместо 16 | Тон станет тише |
| Последнее поле play_request = 0 вместо PAN_CENTER | Mono-тон будет слышен слева |
| Последнее поле play_request = 255 | Mono-тон будет слышен справа |

Частоту и громкость изменяйте в указанных пределах API: 8000..48000 Гц
и 0..64. `TONE_BYTES` должен совпадать с действительным размером массива;
проверка ASSERT в исходнике обнаружит несовпадение при сборке.
Для WAV или MOD сохраняется та же схема: получить номер объекта, загрузить
данные, завершить загрузку, запустить и позднее освободить.

## 3. Обмен с картой

### 3.1. Запрос и ответ

Каждая команда расширенного API - это **запрос** с номером команды и
аргументами и **ответ** со статусом и данными. Аргументы и данные ответа
называются полезной нагрузкой (payload); её размер - от 0 до 128 байт.
Многобайтовые числа представляются в формате little-endian, то есть передаются младшим байтом вперёд: число 1234h занимает два байта 34h, 12h. Выравнивания нет: поля идут подряд, как они объявлены директивами `DB`, `DW`, `DD` в примерах. Точные форматы всех команд собраны в приложении 11.6; смещения там считаются от начала полезной нагрузки.

Одновременно выполняется один запрос: следующий отправляют, получив ответ на
предыдущий. Библиотека выполняет это правило сама. Статус 0 означает успех;
любой другой - код ошибки из приложения 11.2, и тогда данных ответа нет.
`UG_RPC` превращает ненулевой статус в CF=1 и код в A, так что проверка
`RET C` после вызова охватывает и ошибки карты, и ошибки обмена.

Длину ответа проверяют всегда. Ответы фиксированного размера известны
заранее (`UG_OP_…_RESP_LEN`); процедура `rpc` из главы 2 сравнивает BC с
ожидаемым значением и возвращает LENGTH при расхождении. Это защищает от
неверно собранного запроса и от карты другой версии.

Первые команды любой программы - INFO и CAPS. INFO сообщает, что перед нами
UltraGS нужной версии (подпись UGS1, API 1.0, раскладка VLS1), что карта
загрузилась без ошибок (`boot_state=0`) и каков текущий номер сеанса
`session` (3.4). CAPS перечисляет доступные функции битами поля `features` и
поддержанные форматы битами `formats` (11.1). Проверяйте именно тот бит,
который нужен программе: так она честно откажется работать на прошивке без
нужной функции, вместо того чтобы получить непонятную ошибку позже.

Так эти проверки выполняет `check_card` из главы 2. Ожидаемый ответ INFO
записан в программе как подпись: первые восемь байт - `UGS1`, API 1.0,
режим 8 и `boot_state=0`, следующие четыре - раскладка `VLS1`, которая в
ответе лежит со смещения 36:

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#signature -->

```asm
signature:
    DB "UGS1",1,0,8,0        ; magic, API 1.0, режим 8, boot_state 0
    DB "VLS1"                ; раскладка, смещение 36 в ответе INFO
```

<!-- /snippet -->

После первого `compare` регистр DE уже указывает на `VLS1`, поэтому второй
вызов сравнивает раскладку без новой загрузки DE:

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#check-card-info -->

```asm
check_card:
    ld a,UG_OP_INFO
    ld bc,0
    ld ix,UG_OP_INFO_RESP_LEN
    call rpc
    ret c
    ld hl,response
    ld de,signature
    ld b,8
    call compare
    ret c
    ld hl,response+36
    ld b,4
    call compare
    ret c
```

<!-- /snippet -->

Затем процедура проверяет бит 2 поля `features` (передача данных блоками,
которой пользуется `UG_WRITE`) и бит 0 поля `formats` (RAW 8 бит);
несовпадение даёт STATE. Последний шаг - сброс карты `reset_card`,
разобранный в 3.5:

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#check-card-caps -->

```asm
    ld a,UG_OP_CAPS
    ld bc,0
    ld ix,UG_OP_CAPS_RESP_LEN
    call rpc
    ret c
    ld a,(response)
    bit 2,a                  ; бит 2: передача данных блоками
    jr z,.unsupported
    ld a,(response+4)
    bit 0,a                  ; карта понимает формат RAW8
    jr z,.unsupported
    jp reset_card            ; начать с чистой карты
.unsupported:
    ld a,UG_ERR_STATE
    scf
    ret
```

<!-- /snippet -->

Контрольная сумма команд включается вызовом `UG_FRAME_CRC` с A=1: после
этого библиотека добавляет CRC32 к каждому запросу, а карта - к каждому
ответу, и повреждённый обмен обнаруживается кодом CRC. Стоит это несколько
десятков микросекунд на команду; примеры руководства включают проверку сразу
после `UG_OPEN`.

### 3.2. Передача данных блоками

Для звуковых данных есть отдельный механизм - **блочная передача**. Один блок содержит от 1 до 1024 байт. Карта разрешает передачу, принимает ровно столько байт, сколько было объявлено, и подтверждает блок. Библиотечные `UG_WRITE` и `UG_READ` скрывают эти шаги: программа указывает объект, буфер Z80, длину и смещение `UG_OFFSET` внутри объекта.

Загрузка идёт последовательно: каждый следующий блок начинается там, где
закончился предыдущий, поэтому после удачного `UG_WRITE` программа
прибавляет длину блока к `UG_OFFSET`. Так загружается файл любого размера -
глава 6 показывает этот цикл. Читать объект можно с любого смещения в пределах
уже загруженного, в том числе во время его воспроизведения; записывать в
готовый (READY) объект нельзя.

Способ передачи выбирает регистр A. `UG_TRANSPORT_BULK_VERIFIED` (80h)
добавляет к блоку контрольную сумму и даёт уверенность, что данные дошли без
искажений; `UG_TRANSPORT_BULK_FAST` (00h) экономит время на длинных
загрузках, когда целостность проверят иначе, например SEAL с известной CRC
всего файла. Варианты 01h и 81h передают данные через порт GS DATA
и нужны только программам, ограниченным протоколом GS.

Пока блок передаётся, карта принимает лишь служебные команды: INFO, MEM_INFO,
STATS, SNAPSHOT, страницы состояния, OBJECT_INFO текущего объекта и завершение
или отмену самой передачи. Остальные вернут BUSY. При работе через библиотеку
это не создаёт трудностей: `UG_WRITE` возвращается только после завершения
блока.

### 3.3. Ошибки и потеря ответа

Коды ошибок перечислены в приложении 11.2 вместе с рекомендуемым действием.
На практике важны несколько ситуаций.

- **BUSY** - карта занята другой операцией. Ожидание с повтором допустимо,
  но число попыток или время должны быть ограничены, иначе программа
  зависнет при неисправности.
- **PINNED** - объект ещё используется запуском или передачей. Остановите
  свои запуски и повторите FREE через короткое время, как делает `cleanup`
  в примерах.
- **NO_VOICE** - для нового звука нет свободных голосов. Эффект можно
  пропустить или запустить позже; останавливать чужую музыку ради него
  нельзя.
- **STATE** и **HANDLE** - команда не подходит к текущему состоянию объекта
  или номер неизвестен карте. Часто это признак того, что номер устарел
  после смены сеанса (3.4).
- **TIMEOUT** - карта не ответила за отведённое библиотекой время.

Отдельный случай - команда выполнена, но ответ потерян: например, PLAY уже
включил звук, а программа не получила play_id. Повторять такую команду
вслепую нельзя - второй PLAY запустит звук ещё раз. Правильный порядок:
сбросить обмен (`UG_XCTRL` с `UG_XC_TRANSPORT_RESET`), заново прочитать INFO
и убедиться, что сеанс прежний, затем узнать фактическое состояние через
SNAPSHOT, OBJECT_INFO или STREAM_STATE и продолжить с него. Сброс обмена
отменяет неполную передачу, но не откатывает уже выполненные команды.

### 3.4. Сеанс

`session` - восьмибайтовый идентификатор текущего состояния памяти карты.
Карта меняет его при сбросе хранилища и при перезапуске. Программа его не
выбирает и в команды не передаёт; он нужен, чтобы вовремя заметить, что
сохранённые номера объектов и запусков обесценились.

Представьте: программа загрузила звук и получила handle 5. Карту сбросили,
звук исчез, и позже номер 5 достался другому объекту. Продолжая пользоваться
сохранённой пятёркой, программа обратилась бы к чужим данным. Сравнение
сеанса защищает от этого. Сохраните `session` в начале работы: `reset_card`
(3.5) берёт его из ответа RESET_STORE, а программа, которая карту не
сбрасывает, - из поля `session` ответа INFO (смещение 12). Перед
восстановлением после ошибки прочитайте INFO снова и сравните восемь байт с
сохранёнными; если они изменились, старые номера нужно забыть и ничего по
ним не удалять. Так делает общий выход `cleanup` в главе 2:

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#check-session -->

```asm
    ld a,UG_OP_INFO          ; прочитать INFO заново
    ld bc,0
    ld ix,UG_OP_INFO_RESP_LEN
    call rpc
    ret c
    ld hl,response+12        ; поле session в ответе INFO
    ld de,saved_session      ; сеанс, сохранённый при сбросе карты
    ld b,8
    call compare
    jr c,.changed            ; сеанс сменился: старые номера забыть
```

<!-- /snippet -->

`compare` возвращает CF=1 при первом отличии; метка `.changed` завершает
очистку с кодом STATE, не трогая объекты нового сеанса.

### 3.5. Исходное состояние карты

Карта не следит за тем, какая программа что загрузила. После предыдущей
программы на ней могут остаться объекты, играющая музыка, эффекты, открытый
поток или брошенная на середине передача - особенно если та программа
завершилась аварийно. Поэтому программа, которой нужна вся карта, начинает
с команды **RESET_STORE** (06h). Запрос состоит из ключа и уровня. Ключ
55475253h - это буквы «UGRS» (UltraGS Reset Store), прочитанные как число
u32; он защищает от случайного сброса: с другим значением карта отвечает
BAD_ARGUMENT. Уровень 0 - тёплый сброс: карта останавливает всё
воспроизведение, удаляет все объекты и отменяет передачи, а настройки GS
(команды 6Ah и 6Bh) сохраняет. Уровень 1 - холодный: сбрасываются и эти
настройки, после чего выполняется короткая проверка памяти; он нужен
диагностическим утилитам, а не обычной программе. Ответ - новый `session`
(3.4); все прежние номера объектов и запусков недействительны.

Так это делает `reset_card` из главы 2. Перед сбросом она подаёт `UG_XCTRL`
с `UG_XC_TRANSPORT_RESET`: если предыдущая программа оборвалась посреди
передачи блока, карта сама закроет эту передачу только через пять секунд без
данных и до тех пор отвечала бы на RESET_STORE кодом BUSY, а сброс обмена
снимает её сразу:

<!-- snippet:host/sprinter/ultrags/examples/firstpcm.asm#reset-card -->

```asm
; Привести карту в исходное состояние: остановить всё, что играет, удалить
; все объекты и отменить незавершённые передачи. Ответ - новый номер сеанса.
reset_card:
    ld a,UG_XC_TRANSPORT_RESET ; снять передачу, брошенную прошлой программой
    call UG_XCTRL
    ret c
    ld a,UG_OP_RESET_STORE
    ld hl,reset_request
    ld bc,UG_RESET_STORE_REQ_LEN
    ld ix,UG_OP_RESET_STORE_RESP_LEN
    call rpc
    ret c
    ld hl,response           ; ответ целиком - новый session
    ld de,saved_session      ; его копия в памяти Z80
    ld bc,8                  ; идентификатор занимает восемь байт
    ldir
    xor a
    ret

reset_request:
    DD UG_RESET_STORE_KEY    ; ключ 55475253h, буквы «UGRS»
    DB 0                     ; уровень 0: тёплый сброс (настройки GS остаются)
```

<!-- /snippet -->

`reset_request` - пять байт запроса, объявленные директивами `DD` и `DB`;
`UG_RESET_STORE_KEY`, `UG_RESET_STORE_REQ_LEN` и `UG_OP_RESET_STORE_RESP_LEN`
определены в `ug_wire.inc`. Ещё один случай BUSY - незакрытая загрузка файла
командами GS (между 30h и D2h): её закрывает команда D2h (глава 9).
Программа, работающая только командами GS, выполняет тот же тёплый сброс
командой F3h.

Карту сбрасывают в начале работы, а не при выходе: при выходе программа
освобождает только свои объекты и останавливает только свои запуски (4.4).
Не сбрасывает карту программа, которая рассчитывает на объект, загруженный
заранее другой программой: вместо RESET_STORE она читает MEM_INFO и
OBJECT_ENUM (глава 4) и работает с тем, что уже есть.

## 4. Объекты и память

### 4.1. Жизненный цикл объекта

Любой звук проходит одни и те же состояния. ALLOC создаёт объект нужного
вида и размера и возвращает handle; объект находится в состоянии UPLOADING.
`UG_WRITE` переносит данные. Для RAW дополнительно нужен PCM_CONFIG. SEAL
проверяет содержимое и переводит объект в READY; с этого момента данные
неизменяемы, и объект можно воспроизводить сколько угодно раз. FREE удаляет
объект, когда ни один запуск и ни одна передача его не используют.

| Вид (kind) | Константа | Что хранится | Что нужно до SEAL |
|---|---|---|---|
| 0 | `UG_KIND_BLOB` | Произвольные байты, не воспроизводятся | Ничего |
| 1 | `UG_KIND_RAW_PCM` | Отсчёты без заголовка | PCM_CONFIG |
| 2 | `UG_KIND_WAV_PCM` | Файл RIFF/WAVE целиком | Ничего: заголовок разбирает карта |
| 3 | `UG_KIND_MOD` | Файл MOD целиком | Ничего |
| 5 | `UG_KIND_S3M` | Файл S3M целиком | Ничего |

Размер в ALLOC - точный размер данных в байтах; карта округляет резерв вверх
до 16 байт и сообщает его в ответе. Память выделяется одним непрерывным
участком, поэтому для большого объекта важен не общий остаток, а наибольший
свободный участок `largest` из MEM_INFO. Одновременно в сеансе живут не более
128 объектов. Номера объектов не переиспользуются до сброса карты, поэтому
программа, которая много раз создаёт и удаляет объекты, в конце концов
получит NO_HANDLES; счётчик номеров обнуляет только RESET_STORE (3.5).

SEAL с флагом 0 просто проверяет формат. С флагом 1 карта дополнительно
сравнивает CRC32 всего файла с переданным значением - удобно, когда файл
загружали быстрым способом без проверки блоков. SEAL не повторяют для READY
объекта.

**Pin** - признак того, что объект занят. Его ставят воспроизведение,
загрузка и чтение. FREE занятого объекта возвращает PINNED. Остановка
запуска снимает pin не мгновенно, а на ближайшей границе обработки звука,
поэтому после STOP первая попытка FREE может не пройти; повтор через
несколько миллисекунд обычно успешен.

### 4.2. Что сообщить карте о данных

**RAW.** PCM_CONFIG описывает массив отсчётов: частота 8000..48000 Гц,
каналы 1 или 2, разрядность 8 или 16, формат U8, S8 или S16LE (для 16 бит -
только S16LE), начало и длина данных в байтах, при желании внутренняя петля.
Длина должна быть кратна размеру кадра: кадр - это отсчёты всех каналов в
один момент времени, то есть 1 байт для U8 mono и 4 байта для S16 stereo.
Границы петли задаются в кадрах, а не в байтах, и действуют при
воспроизведении с одним проходом (repeats=1).

**WAV.** Карта принимает WAV с одним блоком `fmt` и одним блоком `data`,
mono или stereo, с частотой в тех же пределах, в двух вариантах: обычный PCM
(8 или 16 бит) и сжатый IMA ADPCM (кодек 0x11, 4 бита на отсчёт, блок до
8192 байт). ADPCM-файл занимает на карте вчетверо меньше места, чем 16-битный
PCM, и во столько же раз быстрее грузится; карта распаковывает его при
воспроизведении, а блок `fact`, если он есть, задаёт точную длину. Такой файл
готовит, например, `ffmpeg -i in.wav -c:a adpcm_ima_wav out.wav`. Посторонние
блоки и выравнивание допускаются. Другие сжатые, float- и расширенные
форматы, RIFX и RF64 отвергаются с кодом FORMAT. PCM_CONFIG для WAV не нужен
и запрещён.

**MOD.** Поддержаны модули с 1..32 каналами: `M.K.`, `M!K!`, `FLT4`,
`8CHN`, `FLT8`, `1CHN`..`9CHN`, `10CH`..`32CH`, а также четырёхканальные
15-инструментные Ultimate Soundtracker и Soundtracker IX без сигнатуры.
Файл загружается целиком, как есть; SEAL разбирает заголовок и проверяет
паттерны. Четырёхканальный модуль занимает четыре голоса, восьмиканальный -
восемь, и так далее.

**S3M.** Поддержан профиль с PCM-инструментами (без FM-инструментов и упакованных
образцов), до 32 каналов. Канал с mono-инструментами занимает один голос,
канал, использующий stereo-инструмент, - два. SEAL строит для S3M
дополнительный индекс в памяти карты, поэтому объекту нужно немного больше
места, чем размер файла; MEM_INFO учитывает оба участка, FREE освобождает
оба. Управляют S3M теми же командами, что и MOD.

### 4.3. Что можно узнать об объекте

OBJECT_INFO возвращает вид, состояние (0 загрузка, 1 готов, 2 испорчен),
число pin, размер, сколько байт уже загружено, CRC и разобранные параметры
звука: частоту, число каналов, разрядность и формат отсчётов (у IMA ADPCM -
4 бита и формат 3), длину в кадрах, у модулей - число каналов трекера.
OBJECT_ENUM перечисляет номера всех объектов по возрастанию: первый вызов
с 0, следующий - с полученного номера, ноль завершает обход. Перечисление показывает все объекты карты, а не только
созданные вашей программой: о принадлежности оно ничего не говорит.

MEM_INFO сообщает физический объём памяти, размер пула, свободный объём,
наибольший непрерывный участок и число объектов. Для оценки «поместится ли
файл» нужен `largest`.

### 4.4. Что освобождать при выходе

Программа запоминает номера всех своих объектов и запусков. При выходе -
обычном, по ESC или по ошибке - она:

1. завершает или отменяет свою передачу блока;
2. останавливает свои запуски: CONTROL со своим play_id, STOP_FX со своими
   instance_id;
3. дожидается снятия pin и удаляет свои объекты командой FREE, повторяя её
   при PINNED ограниченное число раз.

Чужие звуки при выходе не трогают. STOP_FX с нулевым номером останавливает
все эффекты карты, RESET_STORE стирает всё хранилище - это действия для
начала работы (3.5), а не для выхода. Объект, который должен пережить
программу (например, загруженный утилитой UGLOAD для следующих программ),
просто не удаляют.

## 5. Воспроизведение

### 5.1. Основной звук

**PLAY_PCM** запускает готовый RAW или WAV как основной звук. Поле `repeats`
задаёт число проходов: 1 - один раз, 2..65535 - столько раз, 0 - повторять
до STOP. `gain` - громкость 0..64, `pan` - положение 0..255 (0 слева, 128 по
центру, 255 справа). В ответ приходит play_id.

**PLAY_MOD** запускает MOD или S3M с начала и тоже возвращает play_id. Флаги:
`UG_MOD_LOOP` (1) повторяет песню после конца; `UG_MOD_IGNORE_F00` (2) и
`UG_MOD_PAUSE_F00` (4) задают, что делать с командой F00 внутри модуля -
играть дальше или остановиться с сохранением позиции. Два последних флага
несовместимы друг с другом и требуют бита 12 в CAPS; без них действует
настройка карты (команда GS 6Ah). Для S3M допустим только LOOP.

Новый PLAY основного звука заменяет предыдущий, но только после полной
проверки нового запуска: если новому не хватает голосов или объект не готов,
прежняя музыка продолжает играть, а команда возвращает ошибку.

**CONTROL** принимает play_id и действие: 0 STOP, 1 PAUSE, 2 RESUME. Пауза
сохраняет голоса и позицию; продолжить можно только из паузы, а не после
конца записи. Ноль вместо play_id означает «текущий основной звук», но для
очистки лучше передавать свой точный номер: так программа не остановит музыку,
запущенную другой программой после неё.

Трекером управляют ещё три команды. **SEEK_MOD** переходит на позицию
`order` и строку 0..63, сбрасывая эффекты каналов и темп на значения по
умолчанию. **SET_TEMPO** меняет скорость (1..31 для MOD, 1..255 для S3M) и
BPM (32..255); команды темпа внутри самой песни позже могут изменить их снова.
**SET_PAN** задаёт панораму логическому каналу трекера 0..31, пока следующий
PLAY, SEEK или команда панорамы в модуле её не заменят.

**SET_MIX** устанавливает четыре общих уровня 0..64: мастер-громкость
музыки и эффектов и дополнительные множители для них. Это общая настройка
карты, она действует на все запуски, включая запущенные командами GS, и не
влияет на OPL2.

### 5.2. Эффекты

**PLAY_FX** запускает готовый RAW или WAV независимо от основного звука и
возвращает instance_id вместе с числом занятых голосов. Поля запроса:
handle, предпочтительный голос (`UG_VOICE_AUTO` = FFFFh, чтобы карта выбрала
сама), приоритет 1..254, громкость, панорама и флаги. Флаг 1 разрешает
вытеснить эффект с меньшим приоритетом, когда свободных голосов нет; флаг 2
повторяет весь объект до остановки. Музыку эффект вытеснить не может. Если
голосов не хватает, stereo-эффект не стартует даже наполовину: ответ
NO_VOICE означает, что не изменилось ничего.

**STOP_FX** останавливает один эффект по его instance_id; объект остаётся
на карте. **CONTROL_FX** приостанавливает и продолжает эффект тем же
набором действий, что CONTROL. Нулевой instance_id в STOP_FX останавливает
все эффекты карты; в обычной программе он не нужен.

Эффект продолжает звучать при паузе и остановке музыки: это разные запуски.
Чтобы при выходе ничего не осталось играть, программа останавливает каждый
свой эффект отдельно.

### 5.3. Громкость, панорама и запас

Все громкости задаются в диапазоне 0..64, где 64 - без ослабления. Для
mono-звука панорама распределяет сигнал между левым и правым выходами; для
stereo она работает как баланс, и в центре оба канала звучат без ослабления.

Сложение многих источников может превысить диапазон 16-битного выхода - это
слышно как искажение. Карта считает такие случаи в счётчике `clip_samples`
(STATS). Чтобы оставить запас, модули с 5..8 каналами ослабляются вдвое,
с 9..16 - вчетверо, с 17..32 - в восемь раз до панорамирования;
четырёхканальные модули, PCM и эффекты играют без ослабления. Если эффекты
поверх громкой музыки искажаются, уменьшите их gain или общий уровень через
SET_MIX.

### 5.4. Голоса

Пул из 32 голосов общий для музыки и эффектов. Восьмиканальный MOD занимает
восемь; оставшихся 24 хватит, например, на 24 mono- или 12 stereo-эффектов.
MOD с 32 каналами или S3M с 16 stereo-каналами занимает всё, и эффекты
получат NO_VOICE. Пауза голоса не освобождает: при продолжении звук должен
начаться ровно с того места, где остановился. Сколько голосов занято сейчас,
показывает поле `voice_count` снимка состояния (глава 8).

## 6. Пример: музыка и эффект поверх неё

**Задача:** включить фоновую музыку из MOD-файла, через секунду добавить
поверх неё короткий эффект, ещё через секунду убрать эффект, а в конце всё
остановить и освободить. Полный текст - [modfx.asm](../examples/modfx.asm);
MOD-файл `GUIDE.MOD` создаётся при сборке примеров и включён в программу
директивой `INCBIN`. Открытие карты, проверки INFO/CAPS, сброс карты
`reset_card` и процедуры `rpc` и `compare` те же, что в главе 2, и здесь не
повторяются. `wait_seconds` ждёт
A секунд по часам DSS так же, как `wait_tone` в главе 2: ESC прерывает
ожидание с кодом CANCELLED, а ошибка звуковой части, замеченная через
SNAPSHOT, - с её кодом. Переменные `music_handle`, `fx_handle`, `play_id` и
`fx_id` в начале программы обнуляются: ноль означает «этого ресурса нет».

<!-- snippet:host/sprinter/ultrags/examples/modfx.asm#modfx-settings -->

```asm
BLOCK_BYTES EQU 1024         ; наибольший блок одной передачи UG_WRITE
TONE_RATE   EQU 8000         ; частота гудка-эффекта
TONE_BYTES  EQU 256          ; длина его массива
FX_GAIN     EQU 32           ; громкость эффекта: 0 = тишина, 64 = максимум
FX_REPEAT   EQU 2            ; флаг PLAY_FX: повторять весь объект
```

<!-- /snippet -->

Порядок действий читается прямо из главной процедуры. Каждый шаг - отдельная
подпрограмма с `RET C` после неё:

<!-- snippet:host/sprinter/ultrags/examples/modfx.asm#modfx-sequence -->

```asm
play_lesson:
    call load_music          ; ALLOC, блоки UG_WRITE, SEAL
    ret c
    call load_effect         ; то же для гудка плюс PCM_CONFIG
    ret c
    call start_music         ; PLAY_MOD с повтором песни
    ret c
    ld a,1
    call wait_seconds        ; секунда одной музыки
    ret c
    call start_effect        ; PLAY_FX поверх музыки
    ret c
    ld a,1
    call wait_seconds        ; секунда музыки вместе с гудком
    ret c
    call stop_effect         ; STOP_FX: музыка продолжается
    ret c
    ld a,1
    jp wait_seconds          ; ещё секунда одной музыки
```

<!-- /snippet -->

### 6.1. Загрузка файла блоками

Файл `GUIDE.MOD` включён в программу целиком, и его размер известен при
сборке:

<!-- snippet:host/sprinter/ultrags/examples/modfx.asm#music-data -->

```asm
music_data:
    INCBIN "GUIDE.MOD"       ; файл MOD включается в программу целиком
MUSIC_BYTES EQU $-music_data ; его размер в байтах
```

<!-- /snippet -->

Файл занимает 2172 байта, а один вызов `UG_WRITE` передаёт не больше 1024
байт (`BLOCK_BYTES`), поэтому загрузка идёт в три приёма: 1024, 1024 и 124
байта. `load_music` выделяет объект вида MOD на весь размер файла, а затем в
цикле передаёт по блоку, каждый раз сдвигая `UG_OFFSET` и адрес источника;
переменная `remaining` хранит число ещё не переданных байтов.
После последнего блока SEAL проверяет заголовок и паттерны модуля. PCM_CONFIG
для MOD не нужен: карта сама знает его формат.

<!-- snippet:host/sprinter/ultrags/examples/modfx.asm#load-music -->

```asm
load_music:
    ld a,UG_OP_ALLOC
    ld hl,music_alloc        ; kind=MOD, размер файла
    ld bc,UG_OP_ALLOC_REQ_LEN
    ld ix,UG_OP_ALLOC_RESP_LEN
    call rpc
    ret c
    ld hl,(response)
    ld (music_handle),hl
    ld (music_seal),hl
    ld (music_play),hl
    ld hl,0
    ld (UG_OFFSET),hl        ; первый блок пишется с начала объекта
    ld (UG_OFFSET+2),hl
    ld hl,MUSIC_BYTES
    ld (remaining),hl
    ld de,music_data
.block:
    ld bc,(remaining)
    ld hl,BLOCK_BYTES
    or a
    sbc hl,bc                ; осталось больше одного блока?
    jr nc,.size_ok
    ld bc,BLOCK_BYTES        ; да: передаём ровно 1024 байта
.size_ok:
    push bc
    push de
    ld hl,(music_handle)
    ld a,UG_TRANSPORT_BULK_VERIFIED
    call UG_WRITE            ; HL=объект, DE=источник, BC=длина
    pop de
    pop bc
    ret c
    ld hl,(UG_OFFSET)
    add hl,bc                ; следующий блок продолжает предыдущий
    ld (UG_OFFSET),hl
    ex de,hl
    add hl,bc                ; источник тоже сдвигается
    ex de,hl
    ld hl,(remaining)
    or a
    sbc hl,bc
    ld (remaining),hl
    ld a,h
    or l
    jr nz,.block
    ld a,UG_OP_SEAL          ; все байты на карте: проверить формат MOD
    ld hl,music_seal
    ld bc,UG_OP_SEAL_REQ_LEN
    ld ix,UG_OP_SEAL_RESP_LEN
    jp rpc
```

<!-- /snippet -->

Вычитание `SBC HL,BC` сравнивает остаток с размером блока: если остаток
больше, перенос установлен и блок ограничивается 1024 байтами. `UG_WRITE`
может изменить BC и DE, поэтому они сохраняются на стеке вокруг вызова.
Так же загружается файл, прочитанный с диска по частям: читать очередную
порцию можно между вызовами `UG_WRITE`, пока окно ISA закрыто.

Эффект в этом примере - тот же 256-байтовый гудок, что в главе 2, и
`load_effect` повторяет шаги 2.3-2.5: ALLOC, UG_WRITE со смещением 0,
PCM_CONFIG, SEAL. Обратите внимание: перед записью во второй объект
`UG_OFFSET` снова обнуляется - смещение относится к объекту, а не к карте.

### 6.2. Запуск музыки и эффекта

<!-- snippet:host/sprinter/ultrags/examples/modfx.asm#start-music -->

```asm
start_music:
    ld a,UG_OP_PLAY_MOD
    ld hl,music_play         ; номер объекта и флаги
    ld bc,UG_OP_PLAY_MOD_REQ_LEN
    ld ix,UG_OP_PLAY_MOD_RESP_LEN
    call rpc
    ret c
    ld hl,(response)
    ld (play_id),hl          ; номер запуска музыки
    xor a
    ret
```

<!-- /snippet -->

PLAY_MOD получает номер объекта и флаги; `UG_MOD_LOOP` заставляет песню
повторяться, пока её не остановят. Через секунду поверх музыки включается
эффект:

<!-- snippet:host/sprinter/ultrags/examples/modfx.asm#start-effect -->

```asm
start_effect:
    ld a,UG_OP_PLAY_FX
    ld hl,fx_play            ; объект, выбор голоса, приоритет, громкость
    ld bc,UG_OP_PLAY_FX_REQ_LEN
    ld ix,UG_OP_PLAY_FX_RESP_LEN
    call rpc
    ret c
    ld hl,(response)         ; первые 2 байта: номер запуска эффекта
    ld (fx_id),hl            ; следующие 2: сколько голосов он занял
    xor a
    ret

stop_effect:
    ld hl,(fx_id)
    ld (fx_stop),hl
    ld a,UG_OP_STOP_FX
    ld hl,fx_stop
    ld bc,UG_OP_STOP_FX_REQ_LEN
    ld ix,0
    call rpc
    ret c
    ld hl,0
    ld (fx_id),hl            ; больше останавливать нечего
    ret
```

<!-- /snippet -->

PLAY_FX не трогает музыку: она продолжает играть всеми голосами, а эффект
получает свой голос. Флаг `FX_REPEAT` повторяет короткий массив, поэтому
гудок слышен ровно столько, сколько пройдёт до STOP_FX. После остановки
эффекта музыка звучит одна ещё секунду. Запросы команд объявлены в одном
месте; номера объектов в них записывают процедуры загрузки:

<!-- snippet:host/sprinter/ultrags/examples/modfx.asm#modfx-requests -->

```asm
music_alloc:
    DB UG_KIND_MOD           ; карта сама разберёт заголовок MOD
    DD MUSIC_BYTES           ; размер файла в байтах
music_seal:
    DW 0                     ; номер объекта запишет load_music
    DB 0                     ; CRC всего файла не задаём
    DD 0
music_play:
    DW 0                     ; номер объекта
    DB UG_MOD_LOOP           ; повторять песню до STOP
music_stop:
    DW 0                     ; номер запуска
    DB 0                     ; действие STOP
fx_alloc:
    DB UG_KIND_RAW_PCM
    DD TONE_BYTES
fx_pcm:
    DW 0                     ; номер объекта
    DD TONE_RATE             ; 8000 отсчётов в секунду
    DB 1,8,0,0               ; mono, 8 бит, U8, без внутренней петли
    DD 0                     ; данные с начала объекта
    DD TONE_BYTES
    DD 0,0
fx_seal:
    DW 0
    DB 0
    DD 0
fx_play:
    DW 0                     ; номер объекта
    DW UG_VOICE_AUTO         ; голос выберет карта
    DB 128                   ; приоритет среди эффектов
    DB FX_GAIN
    DB 128                   ; панорама: по центру
    DB FX_REPEAT             ; повторять, пока не остановим
fx_stop:
    DW 0                     ; номер запуска эффекта
free_request:
    DW 0
```

<!-- /snippet -->

### 6.3. Очистка

Общий выход вызывается всегда: после успешного ожидания, по ESC и при любой
ошибке. Он останавливает ровно те запуски и удаляет ровно те объекты, номера
которых программа успела сохранить; нулевой номер означает «этого шага не
было». FREE повторяется, пока звуковая часть не применит STOP.

`stop_music` устроена как `stop_sound` в 2.7: CONTROL с действием STOP и
своим `play_id`, после чего `play_id` обнуляется. `snapshot` запрашивает
SNAPSHOT через `rpc`; в `free_object` он служит короткой паузой перед
повтором FREE и заодно проверяет, что карта отвечает:

<!-- snippet:host/sprinter/ultrags/examples/modfx.asm#snapshot -->

```asm
snapshot:
    ld a,UG_OP_SNAPSHOT      ; снимок состояния: 64 байта в response
    ld bc,0
    ld ix,UG_OP_SNAPSHOT_RESP_LEN
    jp rpc
```

<!-- /snippet -->

<!-- snippet:host/sprinter/ultrags/examples/modfx.asm#modfx-cleanup -->

```asm
; Общий выход: при успехе, ESC и любой ошибке. Останавливает только свои
; запуски и удаляет только свои объекты, повторяя FREE, пока данные заняты.
cleanup:
    ld a,UG_XC_TRANSPORT_RESET
    call UG_XCTRL            ; закрыть недоконченный обмен, если он был
    ret c
    ld hl,(fx_id)
    ld a,h
    or l
    call nz,stop_effect
    ret c
    ld hl,(play_id)
    ld a,h
    or l
    call nz,stop_music
    ret c
    ld hl,fx_handle
    call free_object
    ret c
    ld hl,music_handle
    jp free_object

; HL = адрес переменной с номером объекта; 0 означает "удалять нечего".
free_object:
    ld e,(hl)
    inc hl
    ld d,(hl)
    ld a,d
    or e
    ret z
    ld (free_request),de
    ld a,64
    ld (retries),a
.retry:
    call snapshot            ; пауза: звуковая часть применяет STOP
    ret c
    ld a,UG_OP_FREE
    ld hl,free_request
    ld bc,UG_OP_FREE_REQ_LEN
    ld ix,0
    call rpc
    jr nc,.freed
    cp UG_ERR_PINNED         ; данные ещё звучат: повторить позже
    jr z,.again
    cp UG_ERR_BUSY
    ret nz
.again:
    ld hl,retries
    dec (hl)
    jr nz,.retry
    ld a,UG_ERR_TIMEOUT
    scf
    ret
.freed:
    xor a
    ret
```

<!-- /snippet -->

Запустите `MODFX0` (или `MODFX1` для второго слота). Ожидается четыре такта
музыки, гудок поверх второй секунды и сообщение `MODFX: music looped, effect
added and stopped, freed`. ESC в любой момент ожидания завершает программу с
кодом 15h (CANCELLED) после той же очистки.

## 7. Поток с диска

### 7.1. Когда нужен поток

Объект целиком хранится на карте. Для длинной записи это неудобно: файл в
несколько мегабайт долго грузится и занимает память. **Поток** решает задачу
иначе: карта держит в памяти кольцевой буфер, программа подливает в него
данные порциями, а карта воспроизводит их по мере поступления. Так можно
проиграть файл, который не хочется хранить целиком, или звук, который
программа создаёт на ходу. Для коротких эффектов поток не нужен - проще
загрузить объект.

### 7.2. Команды потока

STREAM_CREATE создаёт кольцо: в запросе формат отсчётов (как первые восемь
байт PCM_DESC) и три размера в байтах - сам буфер, `prefill` и `low`.
Воспроизведение начнётся, когда в кольце накопится `prefill` байт; когда
запас опустится ниже `low`, карта поднимет флаг «нужно пополнение». Размеры
кратны кадру. Поток на карте может быть только один, и ответ содержит его
handle.

STREAM_START занимает основной звук, как PLAY_PCM, и возвращает play_id.
STREAM_FEED передаёт очередную порцию: номер пакета (первый - 1), длину
1..1024 байт, кратную кадру, способ передачи и, при VERIFIED, контрольную
сумму данных. В отличие от обычной команды, FEED сам содержит передачу блока:
после запроса библиотека дожидается разрешения, передаёт данные и только
потом читает ответ с номером следующего пакета. Отдельный WRITE_END не нужен.
STREAM_EOF сообщает, что данных больше не будет; остаток доигрывается.
STREAM_STATE показывает состояние и счётчики, STREAM_CLOSE освобождает
кольцо. После EOF объект потока сохраняется до CLOSE, чтобы программа могла
дождаться состояния «воспроизведено» и прочитать итоговые счётчики.

Состояния потока: 0 создан, 1 играет, 2 пауза, 3 конец, 4 ошибка,
5 буферизация. Буферизация наступает, когда данные закончились раньше
времени: позиция сохраняется, счётчик `underruns` увеличивается на единицу,
а после нового накопления `prefill` звук продолжается. Именно по этому
счётчику программа узнаёт, успевала ли она подавать данные.

Если ответ на FEED потерян, пакет нельзя отправлять повторно вслепую: он мог
дойти, и тогда данные задвоятся. Сброс обмена, затем STREAM_STATE: поле
`next_sequence` подскажет, какой пакет карта ждёт.

### 7.3. Пример: UGPLAY STREAM

Поток показывает утилита UGPLAY: `UGPLAY STREAM файл.WAV` читает WAV с диска
и подаёт в кольцо содержимое блока `data`. Ключи `/BUFFER:`, `/PREFILL:` и
`/LOW:` задают три размера в КиБ. Для U8 mono 8000 Гц разумны
`/BUFFER:16 /PREFILL:8 /LOW:4`: две секунды запаса, секунда до старта и
полсекунды до опустошения при сигнале пополнения. Файл `GUIDE.WAV` из
комплекта примеров подходит для проверки.

Порядок действий UGPLAY одинаков для любой программы с потоком:

1. STREAM_CREATE с форматом из заголовка WAV и тремя размерами в байтах;
   ответ - handle потока.
2. STREAM_START с этим handle, громкостью и панорамой; ответ - play_id.
3. Цикл до конца файла: прочитать порцию при закрытом окне ISA; выбрать
   длину не больше 1024 байт и не больше свободного места из STREAM_STATE,
   кратную кадру; отправить STREAM_FEED с номером пакета, длиной и способом
   передачи; дождаться бита WRITE_GRANT в X_STATUS; передать байты через
   порт BULK_DATA; прочитать ответ с номером следующего пакета.
4. STREAM_EOF, ожидание состояния 3 по STREAM_STATE, STREAM_CLOSE.

Форматы команд приведены в 11.6. Шаг 3 отличается от обычной команды тем,
что данные передаются между запросом и ответом; в библиотеке эту передачу
выполняет `UG_RPC`, собранный с определением `APP_PLAY`, как в UGPLAY.
Готовая реализация цикла - [ugstream.asm](../lib/ugstream.asm): разбор
заголовка RIFF, выбор длины пакета, VERIFIED с CRC данных и восстановление
после потерянного ответа FEED по `next_sequence`. Программа, которой нужен
поток, берёт этот исходник за основу.

### 7.4. Ограничение

Поток 44100 Гц S16 stereo требует 176 400 байт в секунду без учёта служебного
обмена. На Sprinter с чтением с диска такая скорость пока не достигнута:
слышны паузы, счётчик `underruns` растёт, хотя сам обмен завершается без
ошибок. Больший буфер сглаживает паузы, но не исправляет недостаточную
среднюю скорость. Для mono 8 бит с частотой 8000..22050 Гц запаса достаточно.
Проверяйте `underruns` до и после воспроизведения: успешные ответы FEED и
достижение EOF сами по себе не доказывают, что звук шёл без пауз.

## 8. Наблюдение за картой

### 8.1. Снимок состояния

SNAPSHOT возвращает 64 байта согласованной сводки: номер снимка, сеанс,
счётчик выданных кадров, номер и состояние основного запуска (0 остановлен,
1 играет, 2 пауза, 3 конец, 4 ошибка), вид источника (1 PCM, 2 трекер,
4 поток), handle объекта, позицию трекера (order, row, tick, speed, BPM),
пиковые уровни левого и правого каналов, число underrun, код последней
ошибки звука, количество занятых голосов и эффектов и сведения о текущей
передаче. Снимок не останавливает звук и допустим в любой момент; примеры
этого руководства читают его в цикле ожидания, чтобы вовремя заметить ошибку
звуковой части (поле `last_audio_error`).

### 8.2. Голоса и эффекты постранично

Записи отдельных голосов и эффектов не помещаются в один ответ, поэтому
читаются страницами. Порядок такой: получить SNAPSHOT, скопировать из него
сеанс и номер снимка, затем вызывать VOICE_STATUS или FX_STATUS, передавая
этот ключ, индекс первой записи и число записей (до 5 голосов или 6 эффектов
за страницу). Ответ начинается заголовком с общим числом записей; индекс
увеличивают на возвращённое количество, пока он не сравняется с общим.
Ключ гарантирует, что все страницы описывают один и тот же момент: если
карта успела сделать новый снимок, запрос вернёт STATE, и обход начинают
заново с нового снимка.

VOICE_STATUS перечисляет все 32 голоса, включая свободные: для каждого - номер
запуска, объект, логический канал трекера, позицию в данных, пик, период,
ноту, громкость, панораму и флаги (активен, принадлежит эффекту, на паузе).
FX_STATUS перечисляет только активные эффекты; stereo-эффект - одна запись с
`channels=2`.

### 8.3. Счётчики

STATS возвращает 16 счётчиков: обращения к портам, переданные байты и блоки,
ошибки CRC и протокола, тайм-ауты передач, underrun, ошибки памяти, худшее
время обработки одного кванта звука и одной команды в микросекундах, пиковое
заполнение очередей и число ограниченных отсчётов `clip_samples`. Счётчики
общие для всей карты и растут с момента включения, поэтому программа
сравнивает значения до и после своего сценария. CLEAR_STATS обнуляет их
для всех; в обычной программе он не нужен.

Служебные действия `UG_XCTRL` принимают одно из четырёх значений:
`UG_XC_TRANSPORT_RESET` сбрасывает обмен и отменяет неполную передачу,
`UG_XC_TRANSFER_CANCEL` отменяет только передачу, `UG_XC_CLEAR_ERRORS`
очищает регистры ошибок, `UG_XC_SNAP_LATCH` фиксирует снимок для чтения через
порт SNAP_DATA без команды.

## 9. Команды General Sound

Эта глава нужна, если вы поддерживаете программу, написанную для General
Sound, или хотите, чтобы новая программа работала и с настоящей GS. Для новых
программ только под UltraGS удобнее расширенный API: он возвращает коды
ошибок и длины ответов, тогда как GS сообщает об ошибках отдельным регистром.

### 9.1. Как устроен обмен GS

GS управляется через два регистра. **DATA** передаёт байты данных в обе
стороны, **COMMAND** принимает код команды, а при чтении отдаёт байт
состояния. В UltraGS это порты `BASE+13h` и `BASE+1Bh`; программы с зашитыми
адресами General Sound `00B3h` и `00BBh` работают после `UGCFG GSALIAS ON`,
когда карта отвечает и по этим адресам.

В байте состояния важны два флага. **CB** (бит 0) поднимается, когда записана
команда, и снимается, когда карта её приняла. **DB** (бит 7) показывает, что
в защёлке данных лежит байт: после записи программой он установлен, пока карта
байт не заберёт; после того как карта положила ответ, он установлен, пока
программа ответ не прочитает. Остальные биты состояния равны 1, поэтому
проверяют именно эти два бита, а не весь байт.

Обмен одной командой состоит из коротких шагов. В таблице команд они
обозначены так:

| Шаг | Что делает программа |
|---|---|
| SD | Записывает байт в DATA |
| WD | Ждёт, пока карта заберёт байт из DATA (DB = 0) |
| SC | Записывает код команды в COMMAND |
| WC | Ждёт приёма команды (CB = 0) |
| GD | Читает байт из DATA |
| WN | Ждёт появления следующего байта ответа (DB = 1) |

Порядок всегда одинаков. Если у команды есть **предварительный байт** (pre),
его записывают в DATA до кода команды, без ожидания: карта заберёт его вместе
с командой. Затем SC и WC. Если у команды есть **последующие байты** (post),
каждый передают парой SD, WD. Первый байт ответа читают сразу после WC;
каждый следующий - после WN. У многих команд ответ необязателен: в защёлке
лежит прежнее значение изменённого параметра, и его можно не читать.

Новая команда отменяет недочитанный ответ и незаконченные аргументы
предыдущей. Исключение - состояние загрузки (между 30h/38h/3Eh и D2h): в нём
карта принимает только байты файла и команду D2h, а прочие команды
подтверждает и игнорирует.

Об ошибке команда GS не сообщает: её код остаётся в регистре GS_ERROR
(`BASE+07h`, читается также командой F0h) до явного сброса, а в X_STATUS
поднимается бит GSERR. После важных команд, например запуска модуля,
проверяйте этот регистр.

Библиотечная `UG_GS_COMMAND` выполняет всю последовательность по
девятибайтовому описанию: код команды, признак и значение pre, число и адрес
post-байтов, число и адрес байтов ответа. Между шагами окно ISA закрывается,
а каждое ожидание ограничено тайм-аутом. Короткая обёртка из примера
принимает параметры в регистрах:

<!-- snippet:host/sprinter/ultrags/examples/gsmod.asm#gs-command -->

```asm
; A = команда GS, B = 1 если есть предварительный байт, C = этот байт,
; E = сколько байт ответа прочитать в gs_reply. Библиотека выполняет
; весь обмен флагами CB/DB и закрывает окно ISA после каждого шага.
gs_command:
    ld (gs_desc),a           ; команда
    ld a,b
    ld (gs_desc+1),a         ; есть ли предварительный байт
    ld a,c
    ld (gs_desc+2),a         ; сам предварительный байт
    ld a,e
    ld (gs_desc+6),a         ; сколько байт ответа прочитать
    ld hl,gs_desc
    jp UG_GS_COMMAND

gs_desc:
    DB 0                     ; код команды GS
    DB 0                     ; has_pre: 0 или 1
    DB 0                     ; pre: байт, который уходит до команды
    DB 0                     ; post_count: байтов после команды нет
    DW 0                     ; адрес байтов после команды
    DB 0                     ; число байтов ответа
    DW gs_reply              ; куда положить ответ
```

### 9.3. Загрузка и управление модулем

Модуль загружают командой 30h, затем передают байты файла по одному (SD, WD),
а в конце посылают D2h. Карта проверяет файл и возвращает номер модуля; ноль
означает, что файл отвергнут, и причину можно прочитать командой F0h.
Промежутки между байтами ограничены только терпением программы: карта не
прерывает загрузку по тайм-ауту, поэтому читать файл с диска порциями между
передачами можно. Команда D1h, которой старые программы отмечали начало
данных, допускается, но не обязательна. Пример открывает карту, проверяет
INFO и CAPS и сбрасывает карту так же, как в главе 2 (`reset_card`, 3.5);
программе, которая пользуется только командами GS, тот же тёплый сброс даёт
команда F3h.

<!-- snippet:host/sprinter/ultrags/examples/gsmod.asm#gs-load -->

```asm
gs_load:
    ld a,UG_GS_GS_LOAD_MODULE ; 30h: начать загрузку модуля
    ld b,0
    ld e,1                   ; ответ: номер модуля GS (1)
    call gs_command
    ret c
    ld a,1
    ld (loading),a           ; с этого момента карта ждёт байты файла
    ld hl,music_data
    ld bc,MUSIC_BYTES
.byte:
    ld a,(hl)
    push hl
    push bc
    call UG_GS_SD            ; записать байт в DATA
    jr c,.failed
    call UG_GS_WD            ; дождаться, пока карта его заберёт
.failed:
    pop bc
    pop hl
    ret c
    inc hl
    dec bc
    ld a,b
    or c
    jr nz,.byte
gs_close:
    ld a,UG_GS_GS_LOAD_CLOSE ; D2h: файл передан целиком
    ld b,0
    ld e,1                   ; ответ: номер модуля, 0 при ошибке
    call gs_command
    ret c
    xor a
    ld (loading),a
    ld a,(gs_reply)
    or a
    jr z,.rejected
    ld (loaded),a
    xor a
    ret
.rejected:
    ld a,UG_ERR_FORMAT       ; карта не приняла файл как MOD
    scf
    ret

gs_play:
    ld a,UG_GS_GS_PLAY_MODULE ; 31h
    ld b,1
    ld c,1                   ; предварительный байт: модуль 1
    ld e,1                   ; ответ: 1 = заиграл
    call gs_command
    ret c
    ld a,(gs_reply)
    dec a
    ret z
    ld a,UG_ERR_STATE
    scf
    ret
```

<!-- /snippet -->

`UG_GS_SD` и `UG_GS_WD` - те самые шаги SD и WD в виде библиотечных
процедур; `music_data` и `MUSIC_BYTES` объявлены так же, как в главе 6.
`gs_reply` - буфер в памяти Z80, куда `gs_command` кладёт байты ответа.
Флаг `loading` отмечает, что карта ждёт байты файла, `loaded` - что модуль
принят; оба нужны общему выходу в конце раздела. 31h с предварительным
байтом 1 запускает модуль с начала со стандартным темпом (speed 6, BPM 125);
ответ 1 подтверждает запуск. 32h приостанавливает модуль с сохранением
позиции, 33h продолжает; при MOD эффекты GS продолжают звучать. Полный сценарий примера:

<!-- snippet:host/sprinter/ultrags/examples/gsmod.asm#gs-sequence -->

```asm
play_lesson:
    call gs_load             ; 30h, байты файла, D2h
    ret c
    call gs_play             ; 31h: модуль 1 с начала
    ret c
    ld a,1
    call wait_seconds
    ret c
    ld a,UG_GS_GS_PAUSE_MODULE ; 32h: пауза с сохранением позиции
    ld b,0
    ld e,0
    call gs_command
    ret c
    ld a,1
    call wait_seconds        ; секунда тишины
    ret c
    ld a,UG_GS_GS_RESUME_MODULE ; 33h: продолжить с того же места
    ld b,0
    ld e,0
    call gs_command
    ret c
    ld a,1
    jp wait_seconds
```

<!-- /snippet -->

Текущее положение в песне читают командами 60h (order), 61h (row) и 62h,
ноты и громкости первых четырёх каналов - 63h и 64h, темп - 67h и 68h;
65h переходит к нужной позиции, 66h меняет speed или BPM. 2Ah и 35h задают
мастер-громкость и громкость музыки 0..64.

Очистка в программе GS - команда 37h: она удаляет модуль и эффекты,
загруженные командами GS, и останавливает их звук. Объекты, созданные через
расширенный API, она не затрагивает. Если загрузка была прервана ошибкой,
сначала нужно закрыть её командой D2h - в состоянии загрузки 37h будет
проигнорирована:

<!-- snippet:host/sprinter/ultrags/examples/gsmod.asm#gs-cleanup -->

```asm
; Общий выход. Незаконченную загрузку сначала закрывают D2h: в состоянии
; LOAD карта игнорирует другие команды. 37h удаляет модуль и эффекты,
; загруженные командами GS, и останавливает их звук.
cleanup:
    ld a,(loading)
    or a
    call nz,gs_close
    ld a,(loaded)
    or a
    ret z
    ld a,UG_GS_GS_FREE_LEGACY ; 37h
    ld b,0
    ld e,0
    jp gs_command
```

<!-- /snippet -->

Запустите `GSMOD0`: ожидается секунда музыки, секунда паузы, ещё секунда
музыки и сообщение `GSMOD: module loaded by GS commands, played, paused,
resumed, freed`.

### 9.4. Эффекты GS

Эффект загружают так же, как модуль, но командой 38h для беззнаковых
восьмибитных отсчётов или 3Eh с предварительным байтом формата: 0 для
знаковых (S8), 1 для беззнаковых (U8). Карта хранит до 60 эффектов GS с
номерами 1..60. Команда 2Eh выбирает текущий эффект; команды 40h..49h задают
его параметры по умолчанию: ноту 0..95 (нота 60 соответствует периоду 214),
громкость 0..64, подстройку, приоритет 1..254, маски поиска канала и границы
петли в байтах (три байта: pre и два post).

У GS четыре выхода эффектов GS0..GS3, соответствующие каналам MOD 0, 3, 1, 2.
Команда 39h запускает текущий эффект в свободном канале по маскам поиска,
вытесняя при необходимости эффект с меньшим приоритетом. Команды 80h..83h
запускают эффект прямо в заданном канале; 88h..9Bh делают то же с нотой
и/или громкостью только для этого запуска; A0h..ABh меняют ноту и громкость
уже звучащего эффекта; 3Ah останавливает эффекты по маске (бит 7 - GS0, бит
6 - GS1, бит 5 - GS2, бит 4 - GS3). Пока эффект GS звучит в канале, он
временно заменяет инструмент модуля в этом канале - так работала настоящая
GS. Эффект расширенного API (PLAY_FX) инструмент не заменяет; смешивать оба
способа в одной программе можно.

Однобайтовые номера GS (модуль 1, эффекты 1..60) - не те же числа, что
handle расширенного API. Команда LEGACY_INFO возвращает настоящие handle
текущего модуля, эффекта и незавершённой загрузки, если программе нужно
обратиться к ним через расширенный API, например прочитать OBJECT_INFO.

### 9.5. Отличия от General Sound и NeoGS

| Вопрос | Как ведёт себя UltraGS |
|---|---|
| Команды Z80 внутри платы: 10h..1Fh, прямой DAC 01h..07h, Covox, POKE/PEEK/CALL | Не исполняются: GS_ERROR = 01h. Внутренней RAM, MP3 и SD-карты нет |
| 08h | Пустая команда с подтверждением, а не сброс флагов; сброс флагов - 00h |
| 21h | Свободная память; в старом описании команда ошибочно повторяла номер 20h |
| 23h | Число 32-килобайтных страниц, не больше 255; для 8 МиБ читайте 20h |
| 3Eh | 0 - знаковые отсчёты, 1 - беззнаковые, как в ROM GS; старое руководство утверждало обратное |
| 32h | Пауза с сохранением позиции и ресурсов, а не выгрузка модуля |
| 63h, 64h | Ноты и громкости в естественном порядке каналов 0,1,2,3; бит 7 означает «не менялось с прошлого чтения» |
| 6Ah | 0 - останавливаться на F00 с сохранением позиции, иначе игнорировать F00 |
| F3h, F4h | Тёплый и холодный сброс всей карты со сменой сеанса - то же, что RESET_STORE уровней 0 и 1 (3.5); выполняются в начале работы, а не при выходе |
| F5h, F6h, 69h | Приостановка и возобновление автоматических тиков модуля и один ручной тик; звук не глушится |
| Неподдержанные коды | GS_ERROR = 01h, без зависания; состояние CB снимается |

## 10. AdLib OPL2

### 10.1. Доступ к синтезатору

Карта всегда отвечает на портах AdLib: `0388h` принимает номер регистра и
отдаёт байт состояния, `0389h` принимает значение регистра. Бит 13 поля
`features` в CAPS подтверждает поддержку. Девять FM-каналов
синтезатора не расходуют голоса PCM, а общие уровни SET_MIX на них не
действуют.

Запись в OPL2 - два обращения: номер регистра в `0388h`, затем значение в
`0389h`. Чипу нужно время: не меньше 3,3 мкс после номера регистра и не
меньше 23 мкс после значения. Паузу обычно заполняют несколькими чтениями
порта состояния. Библиотечной команды для OPL2 нет - программа обращается к
портам сама, открывая окно ISA вызовом `UG_ISA_OPEN` (A = слот, HL = 0388h)
и закрывая его `UG_ISA_CLOSE`. Пока окно открыто, порт с номером N доступен
как ячейка памяти C000h + N:

<!-- snippet:host/sprinter/ultrags/examples/fm.asm#fm-ports -->

```asm
OPL_ISA_BASE EQU 0x0388      ; порты OPL2: 0388h адрес/статус, 0389h данные
OPL_ADDRESS  EQU 0xC388      ; те же порты в окне ISA: C000h + номер порта
OPL_DATA     EQU 0xC389
```

<!-- /snippet -->

<!-- snippet:host/sprinter/ultrags/examples/fm.asm#fm-write -->

```asm
; A = номер регистра OPL2, E = значение. Между записью адреса и данных
; чипу нужно не меньше 3,3 мкс, после данных - не меньше 23 мкс; паузы
; заполняются чтением статуса. Окно ISA открыто только на время записи.
opl_write:
    ld (opl_reg),a
    ld a,e
    ld (opl_value),a
    ld a,DOC_SLOT
    ld hl,OPL_ISA_BASE
    call UG_ISA_OPEN
    ret c
    ld a,(opl_reg)
    ld (OPL_ADDRESS),a
    ld b,6
.address_delay:
    ld a,(OPL_ADDRESS)
    djnz .address_delay
    ld a,(opl_value)
    ld (OPL_DATA),a
    ld b,36
.data_delay:
    ld a,(OPL_ADDRESS)
    djnz .data_delay
    jp UG_ISA_CLOSE

; HL = таблица пар "регистр, значение", конец - байт FFh.
write_registers:
    ld a,(hl)
    cp 0xFF
    jr z,.done
    inc hl
    ld e,(hl)
    inc hl
    push hl
    call opl_write
    pop hl
    ret c
    jr write_registers
.done:
    xor a
    ret
```

<!-- /snippet -->

`opl_reg` и `opl_value` - две однобайтовые переменные: `UG_ISA_OPEN` меняет A
и HL, поэтому номер регистра и значение сохраняются до открытия окна.
`write_registers` записывает таблицу пар до байта FFh; так в 10.2 задаётся
инструмент.

Чтение `0389h` возвращает FFh: регистры синтезатора не читаются. Байт
состояния содержит 06h в младших битах, бит 6 - переполнение таймера 1,
бит 5 - таймера 2, бит 7 - общий признак. Таймеры задаются регистрами 02h
и 03h (период (256−значение)×80 мкс и ×320 мкс) и управляются регистром 04h:
биты 0 и 1 запускают таймеры, биты 6 и 5 маскируют их, бит 7 сбрасывает
флаги. Так программы определяют наличие AdLib: сброс флагов, запуск
таймера 1 с периодом 80 мкс и проверка, что через 100 мкс старшие биты
состояния стали C0h.

Ограничение: если в настройках карты включён дополнительный блок портов
BULK alias и он лежит вне 0380h-039Fh, чтение состояния `0388h` надёжно
только при выключенном Turbo (сборка с `UG_ISA_TURBO_OFF`, см. 1.4). С
выключенным alias (настройка по умолчанию) ограничения нет; запись
регистров его не имеет в любом случае.

### 10.2. Инструмент и нота

Каждый из девяти каналов OPL2 образован двумя операторами - генераторами с
собственной огибающей. Один модулирует другой (FM-связь), либо их звуки
складываются. Тембр задают регистры операторов, высоту ноты - регистры
канала. Номера регистров оператора получаются сложением базового номера
со смещением оператора; для канала 0 смещения равны 0 (модулятор) и 3
(носитель).

| Регистр | Назначение |
|---|---|
| 01h | Бит 5 разрешает выбор формы волны регистрами E0h |
| 20h + оператор | Множитель частоты, вибрато, тремоло, удержание уровня |
| 40h + оператор | Ослабление уровня: у носителя это громкость ноты |
| 60h + оператор | Скорость атаки (старшие 4 бита) и спада |
| 80h + оператор | Уровень удержания и скорость затухания после отпускания |
| E0h + оператор | Форма волны 0..3 |
| C0h + канал | Обратная связь модулятора и способ связи операторов |
| A0h + канал | Младшие 8 бит f-number (высоты ноты) |
| B0h + канал | Бит 5 - клавиша нажата; биты 2..4 - октава; биты 0..1 - старшие биты f-number |
| BDh | Глубина вибрато и тремоло; бит 5 включает ударные на каналах 6..8 |

Высота ноты задаётся парой «октава, f-number»: частота = f-number × 49716 /
2^(20 − октава). Для ля первой октавы (440 Гц) при октаве 4 получается
f-number 580 = 244h: в A0h записывают 44h, в B0h - 32h (нажатая клавиша,
октава 4, старшие биты 2). Отпускание клавиши - запись тех же битов без бита
5: 12h. После отпускания звук затухает со скоростью, заданной регистром 80h.

Пример [fm.asm](../examples/fm.asm) настраивает канал 0 и играет эту ноту
одну секунду. Инструмент задан таблицей пар «регистр, значение»:

<!-- snippet:host/sprinter/ultrags/examples/fm.asm#fm-instrument -->

```asm
instrument:
    DB 0x01,0x20             ; разрешить выбор формы волны
    DB 0x20,0x21             ; модулятор: множитель частоты 1, удержание
    DB 0x23,0x21             ; носитель: то же
    DB 0x40,0x18             ; уровень модулятора: ослабить на 18 дБ
    DB 0x43,0x00             ; носитель на полной громкости
    DB 0x60,0xF3             ; быстрая атака, умеренный спад
    DB 0x63,0xF3
    DB 0x80,0x35             ; уровень удержания и скорость затухания
    DB 0x83,0x35
    DB 0xE0,0x00             ; синус у обоих операторов
    DB 0xE3,0x00
    DB 0xC0,0x00             ; FM-связь операторов, без обратной связи
    DB 0xFF
```

<!-- /snippet -->

<!-- snippet:host/sprinter/ultrags/examples/fm.asm#fm-note -->

```asm
NOTE_FNUM_LO EQU 0x44        ; A-4 (440 Гц): f-number 244h при октаве 4
NOTE_KEY_ON  EQU 0x32        ; бит 5 = клавиша нажата, октава 4, f-number[9:8]=2
NOTE_KEY_OFF EQU 0x12        ; те же биты без бита 5
```

<!-- /snippet -->

<!-- snippet:host/sprinter/ultrags/examples/fm.asm#fm-sequence -->

```asm
play_lesson:
    call silence_all         ; снять старые ноты, мелодический режим
    ret c
    ld hl,instrument
    call write_registers     ; тембр канала 0
    ret c
    ld a,0xA0
    ld e,NOTE_FNUM_LO        ; младшие 8 бит высоты ноты
    call opl_write
    ret c
    ld a,1
    ld (sounding),a
    ld a,0xB0
    ld e,NOTE_KEY_ON         ; старшие биты, октава и нажатие клавиши
    call opl_write
    ret c
    ld a,1
    call wait_seconds        ; нота звучит
    ret c
    ld a,0xB0
    ld e,NOTE_KEY_OFF        ; клавиша отпущена: начинается затухание
    call opl_write
    ret c
    xor a
    ld (sounding),a
    ld a,1
    jp wait_seconds          ; слышно затухание
```

<!-- /snippet -->

Перед первой нотой `silence_all` снимает клавиши всех девяти каналов и
выбирает мелодический режим (BDh = 0): предыдущая программа могла оставить
синтезатор в любом состоянии:

<!-- snippet:host/sprinter/ultrags/examples/fm.asm#fm-silence -->

```asm
; Снять клавиши всех девяти каналов и выбрать мелодический режим.
silence_all:
    ld a,0xB0
.channel:
    push af
    ld e,0
    call opl_write
    pop bc
    ret c
    ld a,b
    inc a
    cp 0xB9
    jr nz,.channel
    ld a,0xBD
    ld e,0
    jp opl_write
```

<!-- /snippet -->

У OPL2 нет понятия владельца: карта не знает, чья нота звучит в канале.
Поэтому программа сама распределяет каналы, а при выходе отпускает ровно те
клавиши, которые нажала. Флаг `sounding` отмечает, что клавиша канала 0
нажата; общий выход по нему записывает `NOTE_KEY_OFF`:

<!-- snippet:host/sprinter/ultrags/examples/fm.asm#fm-cleanup -->

```asm
; Общий выход: отпустить свою ноту, если она ещё нажата. Другие каналы
; программа не трогает: у OPL2 нет учёта владельцев, ноты снимает тот,
; кто их нажал.
cleanup:
    ld a,(sounding)
    or a
    ret z
    ld a,0xB0
    ld e,NOTE_KEY_OFF
    jp opl_write
```

<!-- /snippet -->

Запустите `FM0` (или `FM1` для второго слота): ожидается нота, её затухание
и сообщение `FM: note played and released`.

Синтезатор работает одновременно с PCM: музыка MOD и эффекты не затрагивают
регистры OPL2, а остановка музыки не отпускает клавиши FM. Громкость FM
регулируется только уровнями операторов (регистры 40h) и общей настройкой
карты.

Регистр GS_ERROR использует те же коды, кроме двух: нехватка памяти - 10h,
нехватка номеров - 11h; ошибка памяти карты отображается как E1h, неполная
передача - как E0h. Команда F0h читает регистр, не очищая его; очищают 00h вне
загрузки, F3h/F4h и `UG_XC_CLEAR_ERRORS`. Коды выхода утилит DSS с кодами API
не совпадают: например, утилиты печатают TIMEOUT как code 8, ESC как code 10.
