# R10: сокращение задержки CONFIG и выдержка данных

**Обновление 2026-10-20 19:33: R10 REAL FAIL — CATALOG_CRC.**
Замена байта 101 C8→FF воспроизводит computed CRC `DB C4 2D 1F` на фото.
Следующая диагностическая выдача: [R11](CONFIG-PROBE-R11.md).
Ниже сохранены исходные инструкции R10; повторять их серию INFO не требуется.

Исходный статус до проверки: HOST PASS / REAL_PENDING.
Замороженный комплект: `build/config-r10-delivery`.
Версия на карте должна быть `pg-ultrags-compat-r10 v4.1.1`.

## Что установлено

На R9-NOLED последовательность INFO после READY: PASS/PASS/FAIL/PASS/PASS.
В неудачном каталоге замены 44: D3→FF и 123: 00→01 воспроизводят показанный
computed CRC. Это повреждение отдельных полученных байтов; оно не требует
включённой LED-диагностики. Снимки не доказывают электрическую причину.

В коде CONFIG имеет поздний handshake: IOCHRDY утверждается после решения
ARM. При этом PIO до публикации адреса CONFIG выполнял проверки двух
native-диапазонов, заведомо неприменимых к адресам ниже 0200h.
Кроме того, после переключения ADS и включения выходных драйверов WAIT
снимался уже следующей инструкцией PIO — через один такт.
Эти особенности уменьшают временной запас, но их наличие само по себе
не доказывает, что именно они вызвали зарегистрированные ошибки.

## Изменения

* В начале IOR проверяется A9. Низкие порты поступают к ARM напрямую.
  В сгенерированных инструкциях CONFIG публикуется на пять тактов раньше.
  Этот путь не утверждает WAIT до решения ARM и не захватывает соседние
  порты блока 01C0h. Проверка завершившегося/изменившегося цикла сохранена.
* После включения драйверов/ADS WAIT удерживается четыре такта PIO.
  При 370 МГц это около 10,8 нс вместо 2,7 нс внутри RP2040. Это **не**
  измеренное время установки на разъёме и не гарантия достаточности для клона.
* Для сохранения бюджета 22 инструкции native-путь получает через TX FIFO
  абсолютный адрес хвоста ответа вместо отдельной команды и JMP.
  Отмена ранее захваченного native-чтения также использует адрес restart
  с учётом размещения PIO-программы.
* IOW остаётся прежним, 10 инструкций. Независимый предохранитель core1,
  CRC, однократное потребление байта и API VLS1/32 голоса сохранены.
  LED-диагностика отключена. Образы шести других режимов побайтно проверены.

CONFIG всё ещё зависит от задержки ARM. R10 не устанавливает верхнюю
аппаратную границу этой задержки. Нельзя считать восстановление доказанным
по результатам модели или скрывать дальнейший сбой повторами чтения/CRC.

## Автоматические проверки

* Две независимые сборки MULTIFW с одинаковым UF2; проверка инструкций
  из linked ELF, входных файлов сборки, каталога и SRAM.
* 262144 сочетания base/alias/адреса, 1280 CONFIG/GS ответов.
* 12288 случаев в rp2040js: три размещения программы, все 1024 адреса,
  GS on/off и значения обратного входа WAIT; 384 отмены native-чтения.
* Наложение завершения IOW на удерживаемый IOR; mutation без side-set
  должен провалиться. Предохранитель core1 проверяется production C + UBSan.
* Сравнение расписаний R9/R10 при шести заданных задержках ARM.
  Искусственное окно выборки между старым и новым WAIT воспроизводит
  потерю старого ответа и приём нового. Оно служит регрессионной проверкой,
  **не измерением длительности ISA-цикла Sprinter**.
* 213 операций извлечённых CONFIG-обработчиков; 270 сценариев собранного
  UGCFG в Z80-модели. Девять EXE пересобраны и совпадают с предыдущими.
* ZIP/IMG читаются обратно; hashes и источники сохранены в `R10.json`
  и `evidence/`.

Команды и фактические отчёты находятся в комплекте. Аппаратные признаки
на ISA, задержки трансиверов клона, арбитраж SRAM и реальная выборка Sprinter
этими проверками не измеряются.

## Проверка на карте

Прошить `CURRENT.UF2` при выключенном Sprinter; отключить USB до его включения.
Использовать EXE из `CURRENT.ZIP`/`CURRENT.IMG` (они совпадают с R9-NOLED).
Для слота 0:

```text
UGCFG GUS
UGCFG ULTRAGS
UGCFG INFO /DIAG
```

Проверить строку версии R10. Затем выполнить `UGCFG INFO /DIAG` десять раз
подряд и `UGMEM INFO`. Ожидаются только PASS, одинаковый stored/computed CRC,
active08, READY, память 8388608, objects0. Число CRC относится к новому
каталогу и не обязано совпадать с R9.

При первом FAIL сохранить полный экран и остановить серию. SAVE, TRC0,
UGW0 и ожидание кодов LED для этой проверки не нужны.
Для слота 1 добавить `/SLOT:1` к каждой команде.
Успех этой короткой серии ещё не закрывает полный этап S6/S7.
