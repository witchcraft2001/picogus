# R12: выдача каталога из готового SRAM-снимка

Кандидат для Sprinter DX со стоковой прошивкой, без аппаратных доработок.
Версия: `pg-ultrags-cfgfast-r12 v4.1.1`.
Статус: **HOST_PASS / REAL_PASS для серии CONFIG 21:28**, S6/S7 IN_PROGRESS.
Поставка: `build/latest/CURRENT.UF2`, `CURRENT.ZIP`, `CURRENT.IMG`.
Замороженная копия: `build/config-fast12-delivery`.

**Продолжение:** память QUICK и ROUNDTRIP 65537 /VERIFY прошли по сообщению
владельца; UGTEST PCM/FX дали host LENGTH (source01/status03).
Для разбора подготовлена [UGTEST-D1](UGTEST-RPC-D1.md), с прежней R12 UF2.
Постоянный build/latest содержит обновлённую утилиту; перепрошивка не нужна.

## Аппаратный результат 21:28

На фото 21:28:20 переключение в GUS и INFO /DIAG — PASS,
stored/computed CRC `08 34 F4 D2`. На фото 21:28:24 переключение в ULTRAGS
и INFO /DIAG — PASS, active08/boot_result00/READY, CRC `02 2F D2 58`.
Оба CRC совпадают с runtime-каталогами выданной R12.
Владелец сообщил, что повторные INFO также PASS; точное число не указано.
BULK и GS aliases OFF. Результат и hashes фото:
`build/config-fast12-real/r12-real-2128.json`.

Это первый успешный аппаратный прогон после сокращения ARM-пути каталога.
Он поддерживает гипотезу зависимости от времени ответа, но не измеряет
запас времени и не устанавливает физический механизм отказа R11.
Аудионагрузка, передача объектов, GS aliases, SAVE и совместная работа
с другими ISA-картами этой серией не проверены. Следующий этап — память,
передача и аудио по API1-VOICES.md.

Замороженный комплект не перепакован: его статус REAL_PENDING отражает
момент сборки, а настоящий раздел фиксирует последующий аппаратный результат.

## Что установлено по R11

На фото 21:01:38 GUS читает каталог с совпадающим CRC `CA D7 39 5A`.
На фото 21:01:42 ULTRAGS active08/boot_result00, но MODE даёт CRC FAIL,
а следующий INFO — HEADER FAIL. Это два отдельных чтения.
Для полного дампа INFO восемь замен без сдвига потока точно воспроизводят
CRC `5E 7C 17 5E` вместо сохранённого `C0 CC 1F D0`.

| Индекс с нуля | Ожидалось | Получено |
|---|---|---|
| 0 | 55 | FF |
| 14 | 00 | 07 |
| 16 | 01 | FF |
| 17 | 01 | 07 |
| 24 | 00 | 1F |
| 27 | 00 | 01 |
| 43 | 00 | 01 |
| 118 | 00 | FF |

Во всех заменах изменяются только биты 0→1. Это согласуется с неверной
выборкой/выдачей данных, но не определяет электрическую причину. Дамп
переписан с фотографии; положение FF в перенесённой строке нулей сверено
по CRC. Это не бинарный захват ISA.
Скрипт `tools/diagnostics/check-r11-photo.py` сохраняет фотографии/UF2 hashes,
исходный и наблюдаемый CRC в `host/r11-real-2101.json` и восстановленный
поток в `host/r11-observed-catalog.bin` внутри доказательств поставки.

Проба `LATE=00 FLAGS=A4` на фото 20:38 относится к другому чтению. Она
не измеряет момент выборки хостом и не доказывает принятие IOCHRDY.
Нельзя приписывать этот LATE восьми повреждениям в 21:01.

## Изменение

Опция `UG_CONFIG_CATALOG_FAST=ON` действует только для ULTRAGS COMPAT
HANDSHAKE и несовместима с CONFIG_TRACE/CONFIG_PROBE.
При DATA_HIGH с выбранным CMD_FW_CATALOG обработчик читает готовый
core0-снимок непосредственно, записывает ответ в TX FIFO и затем один раз
продвигает индекс. Общий вызов CONFIG для этого байта исключён.
Конец потока и неверный индекс дают FF без продвижения.

Проверка живого цикла и совпадения адреса выполняется до ответа, порядок
IOW→IOR сохранён. После отправки нет условного отката/пропуска индекса:
это могло бы дублировать уже переданный байт. Остальные селекторы, включая
живой CFG_RESULT, продолжают использовать прежний обработчик.

PIO IOW10/IOR22 совпадают с R10. Диапазон раннего WAIT не расширяется на
1C0–1DF; завершения PIO и защита core1 сохранены. LED и проба R11 отключены.
Другие шесть образов побайтно совпадают с R11. Host EXE не менялись.

В обоих linked ARM-образах участок после IO_WAIT до записи байта в FIFO
содержит 15 инструкций для корректного индекса (12 для конца потока).
Это **не оценка полного времени ответа**: входной decode, stale-проверка,
арбитраж SRAM/APB, PIO, трансиверы и выборка хостом сюда не входят.
Ускорение не гарантирует работу, если хост не принимает WAIT.

## Проверки и ограничения

Доказательства и их hashes перечислены в `R12.json`:

- Две независимые сборки UF2, побайтное совпадение.
- Production C: 148 последовательных байтов, конец/неверный индекс,
  смена селектора, LOW без потребления, живой RESULT; отвергнуты мутации
  продвижения до FIFO и условного продвижения после отправки.
- 213 операций production CONFIG и 270 сценариев фактического UGCFG.EXE.
- Исполнение linked Thumb-участка в Unicorn: 37 891 комбинация на каждый
  образ; единственная запись FIFO предшествует изменению индекса.
  Начальное fp=ug_cfg задано явно; полный main этим тестом не исполняется.
- PIO: 262 144 адресных случая, 1280 CONFIG/GS байтов, отдельные
  12 288 случаев и 384 оборванных цикла; проверки guard и бюджетов.
- ZIP/IMG прочитаны обратно с побайтным сравнением файлов.

Эти проверки не заменяют физические измерения и повторные чтения на DX.
CRC-проверка UGCFG не ослаблена, повтором чтения ошибки не скрываются.

## Команды на стенде

Прошить CURRENT.UF2 при выключенном Sprinter; отключить USB до включения.
В слоте 0:

```text
UGCFG GUS
UGCFG INFO /DIAG
UGCFG ULTRAGS
UGCFG INFO /DIAG
```

После ULTRAGS выполнить один INFO даже при FAIL и сфотографировать оба
полных вывода. Проверить строку версии R12. При отказе остановить серию.
Если переключение и INFO прошли, повторить INFO ещё пять раз; остановиться
на первой ошибке. Для слота 1 добавить `/SLOT:1` ко всем командам.

UGCL0/UGCL1 здесь не использовать: регистры пробы R11 отключены.
SAVE и наблюдение кодов LED для этой проверки не нужны.
