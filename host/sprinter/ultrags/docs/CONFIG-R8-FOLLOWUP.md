**Проверка получена, 2026-10-20 16:42:22.** UGW0: native FF→ERROR02,
A2→ERROR00; `SEL=FF PROTO=FF TRACE_SEL=01 RAW=01 FLAGS=9E`.
Запись CONFIG подтверждена, чтение не работает. Повторять эту проверку
не нужно. Следующий кандидат — [R9 COMPAT](CONFIG-COMPAT-R9.md).
Приведённая ниже инструкция относится к замороженному
`build/config-r8-write-delivery`, а не к текущему `build/latest`.

## Аппаратный результат 2026-10-20, 16:24:44

**REAL FAIL** перехода в ULTRAGS. На фото сначала успешный переход в GUS,
затем TIMEOUT ULTRAGS. TRC0 возвращает 16 одинаковых строк:

```text
STATUS=01 ERROR=00 SEL=00 RAW=FF COUNT=FF FLAGS=0E
```

В отличие от R7 native-чтения снова работают. Это не подтверждает исправление
CONFIG или приёмку R8. COUNT насыщается на 255. FLAGS записывается при захвате
CONFIG-чтения, до выдачи данных; `0E` не доказывает, что хост принял IOCHRDY
или увидел ответ. RAW=FF — также начальное значение регистра трассы.

## Исправление трактовки RAW

После обнаружения исчезновения карты UGCFG в `MODE.identified` опрашивает
CONTROL чтениями. Пока получает FF, повторной разблокировки/выбора селектора
не выполняет. TRC0 тоже не делает CONFIG-записей. Поэтому сочетание
SEL00/RAWFF/locked совместимо с полностью исправной записью после reboot.

Это воспроизведено исполнением поставленного UGCFG.EXE на Z80 с отказом только
CONFIG-чтения. После нового запуска прошивки утилита выполнила **ноль записей**,
завершившись TIMEOUT; последующие ручные CC/01 успешно меняют селектор модели.
Отказ чтения здесь инъецирован: тест не устанавливает его физическую причину.

В `ConfigCard` исправлен сброс состояния при reboot/power cycle: selector,
unlocked, pending selector и состояние подтверждения больше не сохраняются
из старого runtime. Firmware globals при настоящем старте сбрасываются.

Остаётся проверяемой гипотеза опоздания CONFIG handshake: в R8 этот путь
обслуживается ARM, native/GS удерживаются PIO. Прежние тесты задержанных ответов
не доказывают, что первый захват/WAIT укладывается в электрический deadline
Sprinter. UGW0 на R4 уже показывал принятую запись при потерянном CONFIG-чтении;
нужно сопоставить это с текущим R8.

## Выполненная проверка — без перепрошивки

Пути на момент выдачи R8 (теперь в `build/config-r8-write-delivery`):

* `build/latest/UGW0.EXE` — известный слот 0, native BASE=02A0;
* `build/latest/UGW1.EXE` — известный слот 1, native BASE=02A0;
* `build/latest/WRPROBE.ZIP` / `WRPROBE.IMG` — только диагностические утилиты;
* `build/latest/CURRENT.UF2` — **тот же R8**, не новое исправление.

Сразу после TIMEOUT, пока native отвечает и LED5 не сработал:

```text
UGW0
```

Если LED5 уже появился, сначала обычное выключение/включение, затем
`UGCFG GUS`, `UGCFG ULTRAGS` и `UGW0`. Для слота 1 использовать `/SLOT:1`
у UGCFG и UGW1. Не выполнять SAVE. При отказе перехода в GUS остановиться.

UGW требует начальные STATUS01/ERROR00, иначе выходит без записей. Выполняет
ровно четыре записи: native CONTROL FF (намеренная ошибка 02), A2 (её сброс),
CONFIG CONTROL CC (разблокировка), 01 (селектор протокола). Нет Flash,
смены режима, reset, операций с объектами или потребляющих DATA/RESPONSE reads.

Нужен полный снимок результата:

| Вывод | Что он устанавливает |
|---|---|
| Native ERROR02, затем ERROR00 | native-запись работает |
| CONFIG SEL01 PROTO04 | CONFIG-запись и эти два чтения работают |
| SELFF PROTOFF, но TRACE_SEL01 RAW01 FLAGS9E | селектор принят, чтения потеряны |
| TRACE_SEL00 RAWFF | после явных CC/01 запись по трассе не подтверждена |

`DIAGNOSTIC COMPLETE` означает завершение утилиты, а не PASS прошивки.
Прямое USB-соединение работающего Sprinter с Mac не требуется.
