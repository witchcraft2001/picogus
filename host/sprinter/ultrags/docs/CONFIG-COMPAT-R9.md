## Что установлено на карте

Фото UGW0 от 2026-10-20 16:42:22 после TIMEOUT R8:

```text
BEFORE: STATUS=01 ERROR=00
NATIVE FF: STATUS=21 ERROR=02
NATIVE A2: STATUS=01 ERROR=00
CONFIG: SEL=FF PROTO=FF TRACE_SEL=01 RAW=01 FLAGS=9E
```

Native-команды и CONFIG CC/01 приняты, селектор стал 01. Отказ относится к
ответу CONFIG-чтения. Ранее SEL00/RAWFF после TRC0 ошибочно рассматривались
как возможное свидетельство отказа записи: UGCFG после первого offline FF
только читает CONTROL, а TRC0 вообще не выполняет CONFIG-записей.

В ConfigCard исправлен сброс selector/unlocked/pending selector при reboot.
Исполнение настоящего UGCFG.EXE с инъекцией отказа только CONFIG-чтения
воспроизводит TIMEOUT и отсутствие последующих записей. Это объясняет
трассу утилиты, но не доказывает электрическую причину отказа.

## Изменение прошивки

R9 использует `UG_ISA_FRONTEND=COMPAT`: отдельные автоматы IOW10 и IOR22,
с теми же словами инструкций, что в прежней рабочей ревизии c711958.
ARM помещает IO_WAIT и ответ в TX FIFO; вывод данных и освобождение шины
выполняет сам PIO. Общий автомат SHARED с принудительным исполнением PIO
инструкций ARM в этой поставке не используется.

Сохранены:

* текущие CLI, API 1.0 VLS1 и пул 32 голосов;
* проверка завершившегося CONFIG/GS-чтения перед потреблением ответа;
* неизменная метка native-принадлежности захваченного цикла;
* защита на core1: при WAIT без завершений более 10 мс отключается ISA;
* синий диагностический LED; первое событие ошибки фиксируется.

Защита учитывает завершения PIO-чтений и обслуженных WAIT-записей.
Отброшенные чужие записи не считаются прогрессом. Обновление карты портов
не удаляет уже захваченное чтение из FIFO.

CONFIG и GS в COMPAT по-прежнему зависят от задержки обработки ARM.
Возвращён прежний механизм обмена; точный момент потери ответа на плате
без измерения сигналов не установлен. Это кандидат восстановления,
а не подтверждённое аппаратное исправление.

Шесть остальных образов режимов побайтно идентичны R8. Настройки Flash и
API не мигрируют. Значение CMake по умолчанию пока SHARED; эта поставка
собрана явно с COMPAT. CONFIG_TRACE отключён: TRC0/1 и поля трассы UGW
не предназначены для этой прошивки.

## Проверка на Sprinter

Прошить **CURRENT.UF2** обычным способом при выключенном Sprinter.
Перед включением Sprinter отключить USB от Mac. Прямое соединение
двух работающих компьютеров для этой проверки не требуется.

Использовать UG*.EXE из CURRENT.ZIP (они пересобраны и совпадают с R8).
Сначала, без GSALIAS и SAVE:

```text
UGCFG GUS
UGCFG ULTRAGS
UGCFG INFO /DIAG
UGMEM INFO
```

Если GUS не прошёл, остановиться и прислать вывод.
Если ULTRAGS дал TIMEOUT, выполнить только `UGCFG INFO /DIAG`, прислать
вывод и число вспышек синего LED; UGMEM при этом пропустить.

Ожидаемый успех: все команды PASS, строка
`firmware=pg-ultrags-compat-r9 v4.1.1`, active=08 ULTRAGS,
boot_state=0, physical/pool/free/largest=8388608, objects=0.
Через две минуты простоя повторить `UGCFG INFO /DIAG` и `UGMEM INFO`.
Ожидаются те же успешные ответы, LED5 появляться не должен.

После этого можно отдельно проверить включение алиаса:

```text
UGCFG /GSALIAS ON
UGCFG INFO
UGCFG GUS
UGCFG ULTRAGS
UGCFG INFO
```

Сразу после включения — GS ON; после смены режима — GS OFF.
Это проверка переключения флага, не приёмка PROPLAY или совместной
работы с другими ISA-картами. SAVE пока не нужен.

Для слота 1 добавлять `/SLOT:1` к каждой команде. Базовый адрес — 02A0.
Не применять TRC0/TRC1 к R9: вместо trace-регистров здесь обычный native API.

## Локальные доказательства

* Две сборки MULTIFW: одинаковый UF2; каталог, CRC, ELF/BIN/UF2 и актуальность
  compiler dependencies проверены для всех образов.
* В обоих связанных ELF проверены IOW10/IOR22, расположение guard в SRAM,
  флаги COMPAT/32 voices/LED и фактическая строка идентификации R9.
* 262144 адресных случая, 1280 CONFIG/GS byte cases, пересечение IOW/IOR,
  отрицательные проверки опоздавшего ответа и ошибочного side-set.
* Независимый rp2040js 1.4.1: 4096 случаев исполнения IOR.
* Production-C CONFIG exchange: 213 портовых операций, отвергнуты мутации
  потребления завершённого чтения, изменения принадлежности задним числом
  и обслуживания IOR раньше предшествующей IOW.
* Production-C guard и LED: проверены остановка core0, timer wrap,
  ложный прогресс, смена карты портов и сохранение pending read.
* Свежий UGCFG.EXE: 270 сценариев на Z80, дифференциальная проверка с C.
  Все девять EXE пересобраны и побайтно совпадают с прежней поставкой.
* Статическая оценка стека parser path с резервом: 1408/2048 байт.

Эти проверки не измеряют электрические задержки Sprinter, качество звука,
PSRAM на физической плате или совместимость PROPLAY. REAL запуск R9 ожидается.
