## Единственное функциональное отличие контрольной сборки

В COMPAT CONFIG ожидает быстрого ответа ARM. В R9 диагностический TIMER_IRQ_1
каждые 25 мс прерывает core0, обслуживающий ISA; также выполняются счётчики
диагностики в горячем цикле. Это дополнительная задержка по сравнению с
прошивкой до диагностики. В ELF R9 IRQ содержит также целочисленное деление.
Фактическая длительность задержки на плате не измерена; не утверждается,
что этот IRQ объясняет все наблюдаемые FF.

R9-NOLED собрана с `UG_LED_DIAG=OFF`. Исключены обработчик LED, его таймер
и счётчики; это проверяется по связанному ELF. Строка идентификации:
`pg-ultrags-compat-r9-noled v4.1.1`. PIO IOW10/IOR22 и его тактирование,
проверка stale read, независимая защита core1, API VLS1/32 голоса, EXE и
алгоритм чтения каталога сохранены. CRC не игнорируется, потребляющие чтения
не повторяются. Светодиод больше не выдаёт диагностические группы вспышек.

## Команды на Sprinter

Прошить CURRENT.UF2 при выключенном Sprinter; отключить USB от Mac до
включения Sprinter. Затем в слоте 0:

```text
UGCFG GUS
UGCFG ULTRAGS
UGCFG INFO /DIAG
```

Если GUS отказал, остановиться. Если ULTRAGS отказал, прислать полный
INFO /DIAG и остановиться. Проверять число вспышек здесь не требуется.

При успехе повторить `UGCFG INFO /DIAG` ещё три раза, затем `UGMEM INFO`.
Через две минуты простоя повторить INFO /DIAG и UGMEM INFO.
Ожидаются PASS, точная строка `compat-r9-noled`, active=08, boot_result=00,
совпадение CRC каталога, boot_state=0 и free/physical=8388608, objects=0.
Не запускать SAVE, GSALIAS или старые TRC/UGW во время этого сравнения.
Для слота 1 добавлять `/SLOT:1` к каждой UG-команде.

Если FF сохранятся, отключение LED не устраняет отказ: следующий анализ —
полный путь core0→PIO относительно момента принятия WAIT, включая polling,
проверку GPIO и арбитраж SRAM. Увеличение таймаута UGCFG не исправляет
уже потерянные байты.

связанные инструкции PIO, SRAM guard и отсутствие LED-диагностики в ELF.
