ИСПРАВЛЕННЫЕ ЗАМЕЧАНИЯ

1. Высокая серьёзность — sw/ultrags/ug_audio.c.
   PIO SM не включался: запуск DMA не запускает I2S. Очередь из трёх
   элементов теряла состояние FULL при head==tail. Буферы не резервировались
   при get(), операции с free_mask могли пересекаться с ISR, повторный RUN
   перезапускал DMA. Исправлены запуск SM один раз, кольцо на N+1 позиции,
   владение FREE/FILLING/READY/DMA и короткие критические секции core1.
   ISR фиксирует pending-mask до W1C. STOP освобождает только READY,
   EOF дожидается queued/in-flight данных; ожидаемая тишина не считается
   underrun. I2S word исправлен: high16 LEFT, low16 RIGHT (pico-extras).
   Проверки: test_device.c, реальный аудиоадаптер с mock SDK, HOST/UBSan PASS.

2. Высокая серьёзность — sw/ultrags/ug_render.c.
   Stereo lane читала соседние mono samples без stride=2; исходный span
   переполнялся до расширения до uint64. Интерполяция округляла delta,
   что меняло half-tie для отрицательного результата. Исправлены stride,
   stereo bounds/ch_off, uint64 multiplication, округление всей weighted
   суммы. FNV-1a теперь считает четыре LE-байта stereo frame со штатным seed.
   Новые независимые проверки на исходном staged-рендере: 4101 FAILURES,
   исходный hash 6b7a489fd3b57694b5887db1ed88c1710195ccf3587f8baca6dc18c9b9bbf136.
   Исправленный код проходит oracle, stereo EOF, UINT32_MAX span и обе
   реальные firmware profiles по 2048 quanta, включая повторный прогон.

3. Высокая серьёзность — ug_diag_link / ug_diag_isa / ug_spike.
   Volatile mailbox перезаписывал ещё не принятую команду, cmd/arg могли
   относиться к разным записям. Status stream читал меняющуюся структуру.
   Введён SRAM mailbox под Pico mutex: core0 использует try-enter, возвращает
   BUSY; core1 принимает целую пару и публикует snapshot короткой копией.
   На STATUS-select фиксируется снимок; конец stream возвращает FF без wrap.
   Проверки включают конкурирующие pthread writer/reader и BUSY при contention.
   Реальный максимум критической секции / IOCHRDY timing требует S1.

4. Высокая серьёзность — ug_psram / ug_spike.
   DMA completion не гарантировал завершение SPI и снятие CS. Следующий
   chunk мог начать команду до окончания предыдущей. Теперь после каждой
   транзакции проверяются DMA, TX FIFO, PC у begin и CS high. Ограничения
   backend соблюдены: read<=31, write<=27, public call<=256 bytes.
   normal/fudge выбираются по плате и проверяются с retry; uninit отключает
   SM, ждёт SPI tail, освобождает DMA/program до повторных claims.
   Неудачный probe и resource audit переводят диагностику в ERR.
   Probe пишет все уникальные MiB-marker patterns до readback для выявления
   aliasing; заявленные 8 MiB остаются неподтверждённой физической ёмкостью.
   HOST проверяет край 8 MiB, chunk counts и lifecycle; электрические свойства
   и пригодность SPI tail condition — REAL_PENDING.

5. Средняя серьёзность — нагрузочный spike и достоверность отчёта.
   Короткие исходные samples полностью помещались в cache после прогрева;
   заявленная нагрузка с постоянными cache misses не проверялась.
   ug_profile.c объединяет sources/setup firmware и host. Музыкальные
   источники 1024 samples сочетают короткие boundary loops и high pitch;
   FX находятся выше 1 MiB, mono/stereo profiles занимают 12 lanes.
   HOST: profile A cache_fills=109418 checksum=25af1bdd;
   profile B cache_fills=124778 checksum=77d47e07 (2048 quanta each).
   Default run=24000 quanta, 64 s rendered audio при 48 kHz, для S1 C00.
   cache_misses отделены от fetch_errors; per-run timing/counters reset.
   Фоновая операция ограничена 256 bytes и выполняется после попытки render.
   Status frames/checksum описывают rendered bytes; STOP может отбросить READY.

6. Средняя серьёзность — бюджеты.
   Первоначальный расчёт суммировал несовместимые SPI-варианты с unused QSPI,
   не проверял PIO1, использовал guessed stack sizes и не показывал запас MVP.
   Теперь SRAM измеряется по ELF sections/addresses для шести mode images,
   bootloader (один core) и NE2K. Stack reserves считаются в scratch banks.
   Flash берётся из BIN lengths + generated slot offsets с реальным upstream
   alignment=1024, 32 KiB boot reserve и последним Settings sector=4096.
   Settings tail проверен ARM compiler без изменения production Settings v5.
   Будущий код, objects/extents, playlist/events, transfer buffers, MOD cache,
   parser scratch перечислены отдельно; measured caches/DMA не дублируются.
   Это ESTIMATE: seven-image catalog/mode8 и full-MVP linker proof — S2+.

7. Средняя серьёзность — tooling / provenance / scope.

   Диагностические selectors перенесены из common/ в private ug_diag.h v2:
   постоянный Ultra GS wire ABI в S0a не вводится.
   Удалены вымышленные copyright строки; собственный новый код GPL-2.0-or-later.
   Лицензии и закреплённые источники: tests/ultrags/reference/sources.json.

УСТАНОВКА И ВОЗВРАТ ДЛЯ S1 (КОМАНДЫ ЗДЕСЬ НЕ ВЫПОЛНЯЛИСЬ)

Закреплённый build picotool собран с PICOTOOL_NO_LIBUSB=1; подходит только для
UF2 creation и file inspection. Команды load/save у него отсутствуют.
Нельзя использовать его как инструмент резервного копирования платы.
Перед S1 flashing сохранить установленный bundle/settings либо явно согласовать
их потерю; USB-capable picotool/recovery tool и его hash закрепить в S1 report.

BOOTSEL mass-storage path на этом macOS, после подготовки стенда:
  shasum -a 256 build/S0a-review/ultrags-diag-release/pg-ultrags-diag.uf2
  cp build/S0a-review/ultrags-diag-release/pg-ultrags-diag.uf2 /Volumes/RPI-RP2/
Возврат сохранённого baseline bundle через BOOTSEL:
  shasum -a 256 build/S0a-review/multifw-release/picogus.uf2
  cp build/S0a-review/multifw-release/picogus.uf2 /Volumes/RPI-RP2/
Hash baseline bundle: 55134c52526b0b885562f881b70d0af3e01f380b4aa72d6274ed53184bf5d9a6.
Эта команда возвращает firmware bundle; сохранность persisted Settings отдельно
проверить на стенде. Standalone UF2 занимает начало Flash, это не slot image;
переключение mode8 через UGCFG пока невозможно. При зависшем ISA снять питание
стенда и выполнять BOOTSEL recovery вне зависшего хоста, как требует §15/S1.
